# 网络配置工具

入口在桌面顶栏「主机管理」旁边的网络图标。工具面向 Windows 的已有 SakuraCat、Windows 企业 VPN 和专用容器隧道，管理配置档、预览差异、应用配置并分层验证。网页运行环境不提供系统网络修改能力。

## 使用

窗口标题栏的「打开网络连接」直接打开 Windows `ncpa.cpl`（经典网络连接窗口），不需要先填写或保存模式。通过受主窗口 IPC 校验的固定动作，交由 Electron `shell.openPath` 打开系统目录中的 applet，不经过 `cmd`/PowerShell，不执行任意输入命令，也不自动启停网卡或修改 VPN、路由。启动失败会在当前窗口提示，可再次点击重试。手动调整系统网络后应返回重新检测和预览；当前未保存输入不会因打开系统窗口丢失。该动作也在参数与执行参考中展示。

窗口标题右侧的「? / 帮助说明」可切换到内置说明页，集中解释家庭/工作两种模式、六阶段配置流程、Windows 路由与 SakuraCat DIRECT 的分层关系、容器 WireGuard/relay 链路、预览应用与回退机制，以及各类校验结果能够和不能够证明的范围。返回配置时当前未保存的表单状态会保留。

1. 选择「家庭网络」或「工作网络」，也可复制并命名一个配置档。选择模式和保存配置档都不会修改系统网络。
2. 打开配置后，工具按「本地代理端口」自动只读检测运行中的 SakuraCat。唯一确认端口所属内核及其 `-f/--config` 路径后，直接显示程序和配置路径，不需要再填写，也不需要先保存才能校验。GUI 程序无法确认时单独显示已识别的内核路径，不把内核误当成客户端启动。已运行时禁用重复启动。
   若没有启动，或权限、多个实例、端口不匹配等原因使配置无法确认，保留手动选择和明确提示。常见 YAML 路径只是排查线索，不自动猜测为当前配置。界面的「本地代理端口」填写实际 mixed-port，不填写控制器端口；进程指定的 `-ext-ctl` 回环控制器由检测独立识别。工具不展示/保存订阅、VPN 密码、PSK、WireGuard 私钥或控制器 secret；登录在原客户端或 Windows 设置中完成。
3. 家庭模式选择已有企业 VPN 的名称和作用域，通过「登录企业 VPN」打开 Windows VPN 设置并连接。工作模式无需连接企业 VPN；到管理网关的实际选路必须为办公物理网卡。
4. 检测当前状态，按步骤检查物理出口、企业管理网、SakuraCat 和容器通道。容器不属于本次目标时，可以关闭该配置档的容器访问选项。
5. 预览配置变更，确认差异后应用。模式切换只操作配置档中明确列出的窄范围路由和专用组件；需要系统管理员权限时会提示。预览后网络发生变化，必须重新预览。
6. 执行链路验证，或在「主机连通性验证」中选择主机管理里保存的主机。主机探测使用主机库最新的地址和 SSH 端口；成功只代表 TCP 建连成功，不代表 SSH 认证或应用业务成功。

### 自动识别的依据与限制

「检测运行中的 SakuraCat」从已知客户端/`com.vortex.helper.exe` 进程取得精简投影，以本地代理监听端口的 PID 确定内核，再解析其显式配置参数和控制器覆盖值。路径、PID、启动时间、端口归属和检测时间直接显示。相对 `-f` 只有与显式绝对 `-d` 同时存在时才解析；没有配置参数时不从常见目录、订阅文件或工作目录猜测。读取配置文件可访问性后再复查一次进程身份，防止进程替换期间显示旧路径。

自动识别只是路径来源证明，不是代理健康验证。后续校验继续用控制器 `/configs`、`/rules` 检查文件与运行态，控制器与代理端口必须属于同一已识别内核。PID/启动时间变化会使已生成的计划失效。客户端在外部重启、切换配置或更改端口后，请重新检测并预览。程序使用未知进程名称、命令行认证覆盖、多个实例共用端口、权限不足等情况会保留人工核验，不会静默改用另一实例。

### 参数与执行参考

模式基本信息、六个阶段以及固定 VPN 绑定区均提供可展开的「参数与执行参考」。它覆盖所有持久化配置字段，同时列出主机 ID、VPN 批量目标、探测地址/端口/协议、修订号、服务名称和动态接口等操作输入。每项参数对应实际动作标识，并展示源码模块、执行函数、只读/探测/修改/启动/保存类别及验证要点。

PowerShell 分支直接从当前版本实际执行的 `NETWORK_SCRIPT` 提取，不维护另一份假脚本。非 PowerShell 动作显示实际函数入口和必要的 HTTP 方法模板。第 5 阶段生成计划后还显示本次真实命令参数和逆操作；计划生成前仅为模板参考。UI 展开只请求代码目录，不执行所展示脚本，更不接受任意命令文本。URL 用户信息、查询串以及密码、secret、token、私钥、订阅和完整进程命令行不出现在参数参考中。

自动识别只提供当前运行参数，手动草稿不被覆盖；「保存模式」可以明确保存识别后的路径。配置持久化格式不变。所有网络修改仍受「预览 → 按计划 ID 应用 → 复查/失败回退」约束，参考面板不能绕过这条链路。

### 将多个目标绑定到固定 Windows VPN

在任一模式的「企业 VPN」阶段，每行输入一个 IPv4 地址或规范 CIDR（也可用逗号、分号分隔，最多 32 项），例如 `10.0.0.199` 与 `10.55.1.0/24`。从已安装的 Windows VPN 中选择名称和作用域，先点「预览」逐项查看当前选路、覆盖范围与冲突，再整批应用计划并点「校验」。重复或相互覆盖的条目会被拦截；单个地址按 `/32` 处理。此项绑定独立于家庭/工作配置档，保存在 Windows VPN 的路由关联里；不会连接 VPN、改变 SakuraCat 设置或改动 WireGuard。需要先在 Windows 中连接所选 VPN，并保持分流模式。

点「刷新当前链路实测」可同时看到所选模式的管理网关与所填目标的 Windows 出口、源地址及匹配前缀，以及运行中的 SakuraCat 对 `10.0.0.0/8` 的 DIRECT 覆盖、模式和 TUN 状态。界面标明快照时间；切换模式、VPN 或修改目标后应重新刷新。DIRECT 只决定代理层处理，不能代替 Windows VPN 的路由。

预览不接受默认路由、小于 `/8` 的宽泛路由、非规范 CIDR、回环与组播地址；若目标覆盖本机地址，或存在走其他接口的同等/更精确路由，则阻止应用。例如现有 `10.204.19.0/24` 经 WireGuard 时，`10.0.0.0/8` 不能宣称整个网段都已绑定企业 VPN。应用后逐项检查 VPN 路由关联和代表地址的实际接口；Windows 在已连接的 VPN 上尚未生成活动路由时，工具核对其活动接口后只补本次输入的精确 ActiveStore 路由。任何新增目标仍未选中 VPN，会撤销本批已确认新增的活动路由与 VPN 关联并报告结果；已有或所有权不明的路由不会误删。之后在「测试一个端点」填写具体 IP、端口和 TCP、HTTP 或 HTTPS。目标 `http://10.0.0.199:8070/ui/` 应使用 `10.0.0.199`、`8070`、`HTTP`；目前端点探测请求根路径 `/`，仅证明该 IP 与端口的 HTTP 服务有响应，不能证明 `/ui/` 页面或浏览器端 `#/workbench/assets` 正常。工具会先确认 Windows 选中指定 VPN，再绕过系统和 SakuraCat 代理直接请求。HTTP 返回状态码（包括 404）证明 Web 服务有响应；路由正确但无响应时，需要继续检查 VPN 对端路由、回程、防火墙和服务端口，不能宣称目标已连接。CIDR 的一个代表地址通过也不证明整个网段可达。

## 两种模式的链路

| 环节 | 家庭网络 | 工作网络 |
| --- | --- | --- |
| 物理接入 | 家庭 Wi-Fi、有线或热点 | 可直达企业网关的办公物理网卡 |
| 企业管理网 | Windows 企业 VPN，按指定前缀分流 | 办公局域网直连 |
| SakuraCat | 保持进程运行，热加载规则模式及内网 DIRECT | 同左 |
| 容器网 | 企业网关 TCP 转发 → 本机转发任务 → 专用 WireGuard 隧道 | 实测物理接口 → 企业网关 → 容器网 |
| 专用隧道生命周期 | 启动并恢复专用任务/服务 | 预览中明确列出停止及自启变化 |
| 验证 | 管理网选路/TCP、外层转发端口、握手、容器选路/TCP、显式代理 HTTPS | 管理网直连、容器下一跳/TCP、显式代理 HTTPS |

内置地址来自该环境的配置示例：管理网 `191.168.0.0/16`、容器网 `10.204.19.0/24`、网关 `191.168.7.62`。`191.168` 和 `162.168` 是有意保留的地址。接口编号、选路和源地址每次重新读取，配置档不保存历史网卡索引。

## 在 Agent 对话中使用

`NetworkConfig` 注册为 cc-haha 的内置工具，默认加载，不需要安装 MCP 或外部 Skill。可以直接问 Agent：「找到网络配置工具」「检查家庭网络配置」「在哪里将 IP 绑定到固定 Windows VPN」「列出已有主机，验证某台主机是否连通」。

- `locate`：返回桌面入口、支持的模式和使用方式，不读取本机配置。
- `list_profiles`、`inspect_profile`：读取与桌面工具相同的配置档，并按当前系统状态给出分层检查和差异预览。
- `verify_profile`：执行指定配置档的目标验证。
- `list_hosts`、`probe_host`：读取主机管理中的主机摘要，并按主机 ID 检查最新地址和端口；不返回账号凭据。

对话工具复用桌面检测实现及当前 `CLAUDE_CONFIG_DIR`，仅开放读取和探测。登录、应用配置和失败恢复继续从桌面网络工具执行，避免两个进程同时修改路由。Agent 返回的检查结果不提供可跨进程复用的计划 ID；应用前必须在桌面重新预览。

## 配置与验证边界

- DIRECT 规则是代理规则，不是 Windows 路由。配置成功、端口可达和 WireGuard 握手是不同证据，界面分别呈现。
- 已有且未被前序规则遮蔽的 `10.0.0.0/8 DIRECT` 可满足容器目标 `10.204.19.0/24` 的代理绕过，无须再插入重复的窄规则。Windows 容器路由仍只针对配置档里的 `10.204.19.0/24`，不会把整个 `10/8` 指向企业网关。
- 模式切换不自动增加 `10.0.0.0/8` 或默认路由。独立的固定 VPN 绑定只有在用户明确输入 `/8`、预览无更精确路由及本机地址冲突时才会尝试，不清空路由表，不操作 `ops-server-v7`。
- 家庭容器接入的「已授权源地址」需与网关实际来源授权一致。本机源地址比较和 TCP 探测不能代替远端 `SSH_CONNECTION`/NAT 的核验。来源变化时，应通过可信主机连接同步核对网关 INPUT 和 relay `-source` 两处限定规则。
- 远端隧道首次安装、密钥生成、远端 ACL 修改仍由现有运维流程完成；工具报告缺失层和需要处理的对象，不复制旧密钥或自动放宽来源限制。
- TCP 可达不能证明业务登录、数据库查询、整个子网的所有端口或 VIP 主备切换。当前自动选路诊断针对 IPv4，IPv6、DNS 和应用自身代理配置需单独排查。

## 持久化和失败恢复

配置档独立保存在应用配置目录的 `network-modes.json`，带版本和修订号，不改变主机库或凭据库。旧的初始格式可向前迁移；未来版本、损坏文档和修订号冲突会阻止覆盖。

应用时主进程保管带有效期的计划，界面只提交计划 ID。执行器使用固定 PowerShell 模板和 JSON 数据，不接受界面提供的命令文本。`network-apply-journal.json` 记录本次修改的逆操作。失败时逆序恢复；若相关字段已由用户或其他程序修改，会保留新值并报告冲突。异常退出留下的未完成事务可通过「恢复未完成切换」处理。

自动化回归使用临时目录、模拟系统状态和回环服务；不连接真实模型，不修改开发者网络。桌面 smoke 使用隔离 fixture，并将模拟证据与真实 VPN 切换验证区分。
