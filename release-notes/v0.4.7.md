# Claude Code Haha v0.4.7

This is a model compatibility and desktop stability release after `v0.4.6`. It adds GPT-5.6 model support and in-page find, and fixes long-task stalls, concurrent permission requests, background task lifecycle, Claude Resume session discovery, duplicate scheduled task output and cross-platform window opening.

Compared with `v0.4.6`, this version further tightens the recovery path for long-running sessions and the boundaries of permission interaction; OpenAI official sign-in can discover and select the GPT-5.6 model family, Kimi K2.7 automatically meets its thinking requirement, and the skills marketplace and session activity panel get a round of visual and interaction polish.

## Highlights

- **GPT-5.6 model support**: OpenAI official sign-in adds catalog, selection and migration support for GPT-5.6, GPT-5.6 Pro and GPT-5.6 Codex, with completed model metadata and session restore paths.
- **More reliable long-task recovery**: after a streaming or WebSocket interruption, long-running turns more accurately distinguish recoverable from completed states, so the UI no longer stays in running for a long time or loses the final assistant output.
- **Safer permission interaction**: concurrent permission requests in the same session are each kept and answered separately; switching permission mode during an active turn is blocked, avoiding mismatches between runtime permission state and the UI selection.
- **Background task lifecycle completed**: background tasks support clearer stop, completion and activity panel state sync, reducing tasks that still show running after finishing or cannot be stopped.
- **Desktop workflows keep converging**: added `Ctrl/Cmd+F` in-page find; Claude Resume can discover desktop sessions; opening a directory from Explorer no longer unexpectedly hides an existing window.

## Fixes

- Fixed long-running model responses possibly getting stuck at watchdog, retry, WebSocket reconnect or assistant commit boundaries, adding recoverable events and final message commit protection.
- Fixed a later request overwriting an earlier one or responses being routed incorrectly when multiple permission / AskUserQuestion requests arrived at the same time.
- Fixed permission mode being switchable while a session was still running; the selector now stays disabled with a clear explanation.
- Fixed background task state not syncing promptly after stopping, the activity panel lacking a stop entry, or tasks lingering in running after they ended (#990).
- Fixed overlapping desktop API polling causing duplicate requests, stale responses overwriting newer state, or abnormal session list refreshes (#993).
- Fixed scheduled task completion output being written to the session twice (#989).
- Fixed the desktop theme setting affecting the Claude CLI output theme; the app theme and CLI configuration are isolated again (#987).
- Fixed Kimi K2.7 requests failing when thinking was not explicitly enabled; the model now automatically uses the required thinking configuration (#986).
- Fixed Claude Resume being unable to discover sessions created on desktop, and session file end-of-write data not being flushed promptly (#988).
- Fixed existing windows being hidden when opening a directory from Explorer because window arguments were reused (#983).
- Fixed update requests wrongly inheriting the provider proxy, quit-and-install errors when installing updates, and an incorrect version layout on the About page.
- Fixed slashes and similar characters in Mermaid labels possibly breaking node shapes, and activity summaries showing an ellipsis too early.
- Fixed the session activity entry showing a meaningless count badge, and the longest task duration in token usage being truncated.

## Features and Improvements

- The OpenAI official provider adds the GPT-5.6 model family catalog, capability information, model selector grouping and migration of old settings.
- Added an in-page find dialog opened with `Ctrl+F` / `Cmd+F`, with navigation between results on the current page (#974).
- The skills marketplace reorganizes search, filters, cards, details, install state, security notices, source status and disclaimer layout, improving readability in narrow windows and dark theme.
- The session activity panel improves display of SubAgents, background tasks and status information, and removes the misleading activity count badge.
- The welcome message is changed to "build, debug and design", better covering how the desktop workbench is used.
- PR quality gates improve deterministic test routing, provider/chat contracts, coverage and environment isolation, reducing the impact of real configuration or external networks on CI evidence.

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.7.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the Git tag `v0.4.7` and `release-notes/v0.4.7.md` must be strictly aligned.
- For official releases, the `Release Desktop` workflow checks that the tag matches the `desktop/package.json` version and loads `release-notes/v0.4.7.md`.
- Auto-update depends on complete installers, blockmaps and standard updater metadata in the GitHub Release: `latest-mac.yml`, `latest.yml`, `latest-linux.yml` and `latest-linux-arm64.yml`.
- Official public macOS releases require signing and notarization secrets; without them only draft/test artifacts can be kept. Windows signing does not block releases, but unsigned installers trigger a SmartScreen warning.
- Before release, run at least `bun run scripts/release.ts 0.4.7 --dry` and `bun run check:impact`; before the official tag, run `bun run verify` and a real `v0.4.6 -> v0.4.7` auto-update smoke test.

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.7-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.7-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.7-win-x64.exe` |
| Windows ARM64 | `Claude-Code-Haha-0.4.7-win-arm64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.7-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.7-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.7-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.7-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If macOS signing and notarization pass verification, the first launch should go through the normal Gatekeeper flow directly.

If it still reports "is damaged" or "cannot verify the developer", the build may still be the unsigned fallback or the local quarantine state has not been cleared; run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.7-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.7-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.7-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
