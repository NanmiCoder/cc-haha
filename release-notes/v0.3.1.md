# Claude Code Haha v0.3.1

This is a fix release focused on **desktop configuration accuracy, workspace references, the terminal experience and cross-platform stability**.

Compared with `v0.3.0`, the focus is not on big new features but on stabilizing desktop details around real project switching, MCP scopes, portable configuration, Windows paths and the terminal panel.

## Highlights

- **More accurate MCP scopes**: the desktop app now distinguishes local / project / user scope following CLI semantics; creating or editing a local/project MCP requires explicitly choosing the target project, so it is never written to the current session worktree or the server's startup directory.
- **More trustworthy MCP settings page**: the settings page aggregates configuration from the active project, recent projects and existing user-private MCP keys; project-scoped entries no longer disappear because the target project differs, and the list no longer flashes empty on first load.
- **Smoother workspace file references**: ordinary dotfiles / dotfolders appear in the file tree, both files and directories can be added to the chat from the workspace menu, and the common copy-path action now copies the project-relative path, with the absolute path kept as an explicit secondary action.
- **More stable portable mode and plugin Skills**: the desktop CLI wrapper carries the selected `CLAUDE_CONFIG_DIR`, and plugins or Skills can be refreshed via reload after installation without restarting the desktop app.
- **More stable terminal panel**: hiding the docked terminal or promoting it to a tab no longer kills a shell you are typing in; the terminal page drops duplicate chrome to leave more usable space, and scrolling while unfocused is improved.
- **More reliable Windows drive root support**: drive-root input such as `C:` / `D:` is normalized, so session, workspace, file access and sidebar hidden-project logic no longer confuse a drive root with its subprojects.

## Fixes

- Fixed interleaved `tool_use ... text ... tool_use` history possibly triggering 400 errors with strict providers such as Bedrock.
- Fixed completed assistant replies being appended again after desktop sleep / wake or reconnect.
- Fixed chat content jittering up and down under Windows WebView2 due to 1px-level height oscillation.
- Fixed the model selector still showing the Claude Official / ChatGPT Official groups when not signed in with OAuth, and fixed the positioning gap between the upward menu and its trigger button.
- Fixed the bypass permission confirmation dialog showing an old project path; the path now follows the active tab.
- Fixed IM adapters reusing a stale session binding after the desktop session was deleted.
- Fixed the shared directory picker menu overflowing the viewport when triggered on the right side of the window.
- Fixed H5 access tests being polluted by the `CLAUDE_H5_AUTO_PUBLIC_URL` environment variable.
- Rolled back the session parent/child tree sidebar display introduced after `v0.3.0`; not allowing branch switching mid-response remains the intended behavior for now.

## Notes

- The GitHub Release body still comes from `release-notes/v0.3.1.md`.
- This version changes MCP local/project/user configuration paths, the portable config directory, terminal runtime lifecycle and Windows drive-root handling; before release, a smoke test of desktop MCP settings, workspace file references, terminal dock/tab switching and Windows paths is recommended.
- Packaged releases are still triggered by tags in GitHub Actions; locally you can first run `bun run scripts/release.ts 0.3.1 --dry` to check that the version and release note are aligned.

## macOS

If the app reports "is damaged" or "cannot verify the developer" on first launch, run:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```
