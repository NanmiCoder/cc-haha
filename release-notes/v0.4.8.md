# Claude Code Haha v0.4.8

This is a desktop workflow, Provider compatibility and security hardening release after `v0.4.7`. It adds Grok official OAuth, the Claude Code Auto permission mode, inline Diff review, conversation navigation and a reasoning effort slider, and fixes lost data directories after Windows upgrades, continuous "thinking" after reconnect, startup failures on restricted ports and covered permission actions.

Compared with `v0.4.7`, this version makes code review, locating content in long conversations and adjusting model reasoning effort more direct; the Windows installer identifies and protects user data in the old install directory before upgrading, and the diagnostics and Doctor flows complete redaction, concurrent writes, corrupted logs and safe repair boundaries. The local service, H5 access and remote preview are further isolated, reducing the risk of cross-origin requests and preview pages gaining desktop permissions.

## Highlights

- **Grok official sign-in**: added xAI Grok official OAuth sign-in, token refresh, a dynamic model catalog and session runtime support, with built-in Grok 4.5 and Composer 2.5 fallbacks, so you can sign in, pick a model and sign out directly on desktop.
- **Claude Code Auto mode**: the permission selector adds an Auto mode with a clear risk warning before enabling; at runtime it reviews tool calls and prompt injection, automatically runs operations it considers safe and blocks high-risk ones.
- **Inline Diff review**: the workbench adds a full Diff review interface with syntax highlighting, old/new line positioning, single-line or multi-line comments, and brings comments and code references back to the chat composer.
- **Better conversation and reasoning controls**: long conversations gain a right-hand navigation outline; model reasoning effort becomes a draggable, keyboard-operable slider that keeps the levels available for the current Provider / model and the session's selection.
- **Windows upgrade data protection**: the NSIS installer identifies, verifies and restores historical data in the install directory before uninstalling the old version, so providers, sessions, Skills, memory or custom data directories are not removed by an upgrade.
- **Tighter desktop security boundary**: local service requests carry a separate access credential, and H5 / reverse proxy traffic is judged separately from trusted desktop traffic; remote preview uses an isolated session and denies camera, microphone, notifications and similar permissions by default.

## Fixes

- Fixed leftover thinking state after a WebSocket reconnect possibly continuing to show "Thought" and consuming tokens (#1002).
- Fixed Markdown preview or other overlays possibly covering permission action buttons; the approval entry stays visible (#932).
- Fixed the desktop app or H5 being unable to connect to the local service on Windows and other platforms after randomly getting a browser-restricted port (#961).
- Fixed Windows upgrades possibly deleting historical configuration and session data in the install directory; the recovery flow verifies the source, user identity and copy results, and stops the install on ambiguity instead of guessing a migration; reinstalls in default mode with no old directory data are no longer wrongly blocked by recovery protection (#959, #973, #1000).
- Fixed switching to Auto mode taking several seconds, switching from skip permissions possibly triggering an extra restart, and the first confirmation state not being kept correctly (#978).
- Fixed syntax highlighting, file status, line selection, selection breaking after collapse and lost code reference cards in Diff review, and made highlighting closer to Codex (#1004).
- Fixed alignment, overlap and narrow-window layout issues between long conversation navigation and the composer, message content and workbench panels (#782).
- Fixed the reasoning effort popover being too large, the selection not being restored with the session, and mismatched levels after switching models (#1007).
- Fixed inaccurate statistics and unstable export of diagnostic logs under concurrent writes, segment rotation or corrupted records; diagnostic bundles and Issue reports are redacted as far as possible with limited content scope.
- Fixed Doctor / runtime recovery possibly crossing the safe UI state boundary; user data such as chat history, model configuration, Skills, MCP, IM and OAuth stays read-only protected.
- Fixed remote or proxy-marked requests possibly being misjudged as local trusted requests, and remote preview pages possibly inheriting desktop session permissions.

## Features and Improvements

- Added a Grok official Provider settings page, browser OAuth callback and polling, secure credential storage, automatic refresh, model capability information and Provider runtime environment injection.
- Auto mode runs through the CLI, desktop, session creation, WebSocket recovery, the permission classifier and persisted settings; switching permissions during an active turn stays blocked, avoiding mismatches between runtime state and the UI selection.
- Conversation navigation builds a scannable outline from user messages, supports quick jumps, and gives clearer interaction feedback near the navigation area.
- The workbench moves to a more compact file / Diff review layout, with changed file filtering, preview tabs, file status, code selection and review comment references.
- The reasoning effort slider supports mouse dragging, click selection, arrow keys, Home / End and accessibility state, and exposes the levels each model actually supports, such as low / medium / high.
- The diagnostics page adds a more complete retention policy, corrupted record notices, event IDs, redacted Issue reports, export bundles and safe UI state repair feedback.
- Merged community security hardening PR #1015 and continued strengthening local access isolation tests for adapters, REST, WebSocket, Electron IPC and the updater.
- The release workflow adds a self-check of the Windows historical data recovery script and fresh install / default-mode reinstall smoke tests of the compiled installer, ensuring installers cover key upgrade protection paths before release.

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.8.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the Git tag `v0.4.8` and `release-notes/v0.4.8.md` must be strictly aligned.
- For official releases, the `Release Desktop` workflow checks that the tag matches the `desktop/package.json` version and loads `release-notes/v0.4.8.md`.
- Auto-update depends on complete installers, blockmaps and standard updater metadata in the GitHub Release: `latest-mac.yml`, `latest.yml`, `latest-linux.yml` and `latest-linux-arm64.yml`.
- Official public macOS releases require signing and notarization secrets; without them only draft/test artifacts can be kept. Windows signing does not block releases, but unsigned installers trigger a SmartScreen warning.
- H5 or reverse proxy access still has to be explicitly enabled with a Token / CORS configured; the desktop built-in preview never sends the local access credential to non-local service origins.
- Before release, run at least `bun run scripts/release.ts 0.4.8 --dry` and `bun run check:impact`; before the official tag, run `bun run verify` and a real `v0.4.7 -> v0.4.8` auto-update smoke test, with particular attention to Windows user data being fully preserved.

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.8-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.8-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.8-win-x64.exe` |
| Windows ARM64 | `Claude-Code-Haha-0.4.8-win-arm64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.8-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.8-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.8-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.8-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If macOS signing and notarization pass verification, the first launch should go through the normal Gatekeeper flow directly.

If it still reports "is damaged" or "cannot verify the developer", the build may still be the unsigned fallback or the local quarantine state has not been cleared; run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**. Before removing the old version, the installer checks for data that needs to be recovered; if it detects an old version still running or a data directory it cannot safely assess, it keeps the old version and the original data and asks you to resolve it and try again. If the installer says it is running with too many privileges, just double-click it; do not use **Run as administrator**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.8-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.8-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.8-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
