# Claude Code Haha v0.3.0

This release focuses on **desktop long-session performance, streaming tool previews, AskUserQuestion stability, multi-client streaming subscriptions and H5 network reliability**.

Compared with `v0.2.9`, the core work is a systematic performance overhaul of desktop long sessions: from stabilized virtual scrolling, React component memoization and Markdown cache optimization to persistent cross-tab height caching, large sessions with 800+ messages no longer show white screens or stutter when scrolling or switching tabs. Streaming Writer previews and pending tool cards make long tool execution visible, and AskUserQuestion and multi-client IM streaming subscriptions received targeted reliability fixes.

## Highlight

- **Much faster desktop long-session scrolling**: a 797+ message / 2.6MB session went from 1-2s of white screen to 0s white-screen samples (all 34 scroll positions pass), achieved with a stable 1200px overscan, React 18 automatic batching, batched ResizeObserver callbacks per frame and removing flushSync from the scroll handler.
- **Memoized React component tree**: six heavy components including AssistantMessage, UserMessage and ToolCallBlock are wrapped in React.memo; branchAction/toolResult lookups are lifted into useMemo Maps, so unchanged rows skip re-rendering when the window slides.
- **Reworked Markdown cache**: the cache key changes from the full content string to a `${len}:${fnv1a}` hash, split into 200 finalized entries (8MB) + 4 streaming entries, so streaming no longer evicts finished parses; VirtualSpacer renders in chunks, eliminating scroll white screens.
- **Persistent cross-tab height cache**: added virtualHeightCache (a module-level LRU keyed by sessionId), so switching back to a visited session reuses measured heights and skips the estimate-to-measure correction; O(N) branch/completion calculations are deferred with useDeferredValue.
- **Streaming Writer preview and pending tool card**: a long Write renders a pending tool card as soon as tool_use_start arrives and updates the input preview from deltas; Write.content is decoded into a lightweight plain-text preview window, and the full diff rendering is kept after completion.
- **AskUserQuestion stability**: the CLI's toolUseResult metadata is no longer lost in the desktop bridge; live SDK permission requests are tracked and replayed on reconnect; custom answers are upgraded to a multi-line editor (Ctrl/Cmd+Enter to submit).
- **Multi-client streaming subscriptions**: the WebSocket handler broadcasts session messages per client, so opening the same session on desktop no longer "steals" Telegram's stream; long Telegram answers are chunked automatically and thinking deltas accumulate.
- **More stable H5 LAN links**: a manually selected LAN address refreshes to the current port after the sidecar port changes; a manual LAN host is no longer overwritten by auto-discovery results from WSL/Docker virtual network adapters.

## Main updates

### Desktop long-session performance (systematic optimization across 6 commits)

- Long conversations switch to a dynamic virtual window based on measured heights, while short conversations stay fully mounted; the content-visibility full-list approach is dropped to avoid WebView white screens.
- Virtual scroll overscan changes from dynamic growth (360px to 7200px) to a fixed 1200px; flushSync is removed from the scroll handler so React 18 automatic batching handles state updates.
- ResizeObserver height callbacks set a pending bit and trigger setMeasuredItemsVersion only once per frame, instead of a full-list re-render per item; auto-scroll from measurement feedback is removed to avoid fighting the user's scrolling.
- The TabBar's chat-store subscription is narrowed to running-state ids, so streaming payload churn no longer causes needless tab chrome re-renders.
- AssistantMessage, UserMessage, ToolCallBlock, ToolCallGroup, ToolResultBlock and MarkdownRenderer are all wrapped in React.memo; per-message branchAction/toolResult lookups are lifted into a useMemo'd Map.
- The Markdown cache key becomes a `${len}:${fnv1a}` hash; a 200-entry 8MB finalized cache + 4-entry streaming cache, with caching no longer disabled during streaming; VirtualSpacer splits spacers into ~800px chunks, combined with content-visibility: auto + contain-intrinsic-size to eliminate white screens.
- virtualHeightCache (a module-level LRU keyed by sessionId) restores historical heights and the metric map on tab switch; closing a tab releases the cache via tabStore.closeTab to dropSession. getBranchableMessageTargets / getCompletedTurnTargets render at low priority with useDeferredValue(messages).

### Streaming tool preview

- On tool_use_start a pending tool_use message is upserted; deltas update a lightweight input preview; on tool_use_complete it is updated in place to the full card, avoiding duplicate cards.
- During the pending phase, Write.content is decoded into a bounded plain-text preview window, and the existing full diff rendering is kept after completion.

### AskUserQuestion reliability

- Structured toolUseResult answers from the CLI transcript are transmitted consistently in history replay and live WebSocket tool results, so answered cards correctly show the resolved state.
- Live SDK permission requests are tracked and replayed to new clients on reconnect; sessions waiting for user input get a longer cleanup grace period; aborted results render as completed history instead of an unanswered prompt.
- The custom answer input is upgraded to a multi-line editor with Ctrl/Cmd+Enter to submit; fixed duplicate unanswered cards when history restore overlapped with a live permission request.

### Multi-client streaming subscriptions

- WebSocket session output now tracks callbacks per client and broadcasts messages instead of replacing earlier subscribers; desktop and Telegram can watch the same streaming session at the same time.
- Telegram thinking deltas accumulate and edit the placeholder message instead of replacing it with the latest small chunk each time; long answers automatically seal full chunks and open a new editable placeholder to fit Telegram's message length limit.

### H5 LAN links

- The manual LAN address settings UI supports separate host/IP input and reuses the current server port; it is no longer overwritten by auto-discovery results from WSL/Docker virtual network adapters.
- Plain HTTP private LAN URLs refresh to the current dynamic port automatically after a sidecar restart; reverse proxy URLs are left unchanged.

### Worktree UI

- The desktop chip for worktree sessions hides internal branch labels (such as worktree-desktop-*) and slugs, showing only the source project and a worktree marker.
- The git-info API distinguishes launch branch metadata from the branch actually checked out in the worktree, and switches to the actual branch only after the session enters the worktree.

### Other improvements

- The OpenAI proxy stream timeout applies only to establishing the upstream connection and no longer truncates SSE generation that has already started.
- The filesystem browser registers the resolved workspace root, supporting file search for Windows projects on other drives (such as D:\workspace).
- Computer Use rejects Python runtimes below 3.9, pins Pillow to the compatible 11.x line, and falls back to the default PyPI when installing from a configured mirror fails.
- Shiki syntax highlighting is now lazy-loaded and falls back to Prism when older WebKit fails to parse it, avoiding startup crashes in the macOS 12 WebView.

## Fixes

- Fixed 1-2s white screens when scrolling long sessions (flushSync blocking the compositor + dynamic overscan growth + many synchronous ResizeObserver re-renders).
- Fixed large virtual scroll spacer divs leaving the WebView with nothing to paint, causing scroll white screens.
- Fixed the Markdown cache using the full content string as the key, causing frequent eviction in large sessions and streaming chunks evicting finished parses.
- Fixed every row re-rendering from scratch when the window slides (no memo barrier + object literals recreated on every render).
- Fixed heights and the metric map being cleared when switching back to a visited session tab, forcing a full estimate-to-measure correction.
- Fixed long Write tool calls showing no visible progress before tool_use_complete.
- Fixed AskUserQuestion still showing as unresolved after answering, duplicate cards on history restore, and reconnects killing the CLI with an AbortError.
- Fixed Telegram losing stream content and completion events after the same session was opened on desktop.
- Fixed long Telegram answers stopping updates after exceeding the message length limit, and the preview shrinking because thinking deltas were replaced with the latest small chunk each time.
- Fixed H5 LAN links keeping a stale port after a sidecar restart, and manual LAN hosts being overwritten by auto-discovery.
- Fixed the OpenAI proxy stream being truncated by the full-request timeout, stopping long SSE generation midway.
- Fixed worktree sessions showing the source branch or internal ref labels (worktree-desktop-*).
- Fixed files in Windows projects on other drives not being searchable in the filesystem browser.
- Fixed the desktop compact state getting stuck after auto-compact or cancellation.
- Fixed Computer Use failing to install dependencies with older Python versions.
- Fixed startup crashes when older Safari/WebKit parsed Shiki's modern RegExp syntax.

## Other notes

- The GitHub Release body still comes from `release-notes/v0.3.0.md`, so the Markdown does not have to be copied by hand.
- The desktop performance work changes virtual scrolling, React memo, caching and layout paths; if you see scrolling glitches or height calculation problems after upgrading, it is usually a compatibility issue between the measurement cache or spacer chunks and a specific WebView version. Please report the session size and WebView version.
- Streaming Writer previews and pending tool cards depend on the provider correctly sending tool_use_start and input delta events; if a provider only sends tool_use_complete, the pending card will not appear but the final card renders as usual.
- This version includes many desktop rendering and layout path changes; a real long-session scroll + tab switch smoke test is recommended on each of macOS WebKit, Windows WebView2 and Linux WebKitGTK.
