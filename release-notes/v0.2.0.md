# Claude Code Haha v0.2.0

This is a milestone release that brings together the desktop Coding Agent workflow capabilities from the last several releases: from Slash Commands, terminal tabs and Provider configuration to workspace file management, change review, revert, diagnostic export and release quality gates, the desktop app has grown from "can run the CLI" into a more complete local Agent workbench.

Compared with `v0.1.9`, the new focus is quality gates and diagnostics: the project now has three layers of quality gates (PR, baseline and release), and can verify the core Agent pipeline with real provider/model baselines and a desktop browser smoke test. The desktop app also adds an exportable, redacted diagnostic bundle so users can provide useful troubleshooting information for startup failures, provider errors and runtime exceptions. This release also fixes lag with large session histories, custom titles being overwritten, DeepSeek requests failing with thinking disabled, light panels in the dark inspector, and lost historical workspace changes on Windows.

## Highlight

- The desktop workbench takes shape: the `/status`, `/cost` and `/context` visual inspector, terminal tabs, the workspace file panel, file preview, chat context file chips and the current-turn changes card now form one complete workflow.
- More reliable change review and revert: the desktop app shows file changes from the current turn and the whole session, displays diffs in both Git and non-Git directories, and reverts to the corresponding user message via checkpoint rewind.
- Much better third-party Provider compatibility: Provider configuration, the Kimi coding endpoint, DeepSeek disabled thinking, WebSearch fallback, provider fallback for old sessions and consistent thinking parameters all received focused improvements.
- Better desktop troubleshooting: startup failures, runtime exits, WebSocket errors and provider test failures go into a unified diagnostic log, and users can copy a summary or export a redacted diagnostic bundle from settings.
- A release quality system is in place: PR impact analysis, change-scope gates, real model baselines, a desktop browser smoke test and a release gate mean releases no longer depend on unit tests alone.

## Main updates

- Added PR quality gates: the affected areas (desktop, server, adapters, docs, release, cli-core and so on) are detected automatically from changed files and the matching checks are triggered.
- Added a PR impact report: run `bun run check:impact` locally to see changed areas, suggested check commands, missing test signals and high-risk path warnings.
- Added a PR triage workflow: it labels PRs by area, generates a risk summary, and requires maintainer confirmation via `allow-cli-core-change` for CLI core changes.
- Added unified quality gate commands: `bun run quality:pr`, `bun run quality:gate --mode baseline` and `bun run quality:gate --mode release` write structured reports to `artifacts/quality-runs/`.
- Added real model baselines: maintainers can run fixture tasks with a local provider/model selector to verify the agent's search, editing, failure recovery, cross-module changes and artifact generation.
- Added a desktop browser smoke baseline: the quality gate can start the local server and the Vite desktop app, create a session in a real browser, select a provider/model, send a task, and judge pass/fail by the file diff and test results.
- Added `bun run quality:providers`: lists the provider/model selectors available on the machine, so the release gate does not depend on provider UUIDs on a particular machine.
- Added a desktop diagnostics settings page: view recent events, open the log directory, copy an error summary, clear logs and export a diagnostic bundle.
- Added server-side diagnostic storage: CLI startup failures, runtime exits, WebSocket user message failures, provider test failures and similar errors are written as structured diagnostic events.
- Diagnostic export strips sensitive information: chat content, file content, full environment variables, API keys, Bearer tokens, cookies and OAuth tokens are never exported.
- The README, CONTRIBUTING and Chinese/English docs add contribution and quality gate guidance, so contributors can run local checks and live baselines as the project requires.
- AGENTS.md adds quality gate rules: Coding Agents must run the matching gate, or clearly state what blocks it, before declaring a PR or release ready.

## Recent capabilities brought together

- The desktop Slash Command panel supports session inspection with `/status`, `/cost`, `/context` and more, and handles local commands such as `/help`, `/clear`, `/compact` and `/plugin`.
- The terminal has become a desktop tab workflow, so multiple terminal tabs can be opened and kept inside the desktop app.
- The Provider settings page has an API Key entry, show/hide key, local provider guidance, and presets for Jiekou AI, Shengsuan Cloud, LM Studio, Ollama and others.
- The right workspace file panel lets you browse the project directory, preview text and local images, see added/modified/deleted files, and add files or partial content to the chat as context.
- Choosing a project directory on the start page immediately creates a draft session, so file management, the changes view, runtime selection and the terminal toolbar are available before the first prompt.
- When reloading a past session, `@file-path` references in the transcript are restored as attachment chips, so long absolute paths no longer appear in the user message body.
- WebSearch settings support Auto, Tavily, Brave, Claude native and Off, and fall back to Tavily / Brave when a third-party model does not support the native server tool.
- Closing the main desktop window keeps the app running in the tray; the local server and adapter sidecars are not stopped by an ordinary window close.
- The desktop app remembers the main window size, position and maximized state and restores them on restart, avoiding off-screen placement when external displays change.

## Fixes

- Fixed DeepSeek / Anthropic-compatible endpoints still receiving the effort parameter with thinking disabled, which made the upstream return 400; explicitly disabled thinking requests no longer send effort.
- Fixed inconsistent thinking parameters for third-party Anthropic-compatible Providers across the main session, side queries and AI title generation, reducing request failures from mismatched model capabilities.
- Fixed WebSearch sometimes being unavailable with third-party Providers due to the `web_search_20250305` schema, proxy-layer capabilities or non-Claude model names.
- Fixed the desktop `/status`, `/cost` and `/context` inspector still showing light panels in dark mode; these panels and the MCP switch now use theme tokens.
- Fixed sidebar lag caused by large session histories: the session list now pages by file modification time first and then reads the JSONL for the current page only, instead of parsing all history at once.
- Fixed automatic titles sometimes overwriting custom session titles; later AI title refreshes are skipped when a custom title exists.
- Fixed deleted draft sessions sometimes being recreated by the prewarm startup flow; deleting a session now also stops and marks its runtime.
- Fixed too little error information when the CLI fails at startup or exits unexpectedly at runtime; redacted stdout, stderr and SDK error summaries are now captured for the UI and diagnostic log.
- Fixed unreliable relative path detection for workspace files caused by Windows path casing and drive letter handling.
- Fixed lost workspace changes in past sessions: the workspace panel merges session tool records with file-history checkpoint snapshots, so changes from earlier turns are shown even if the current Git state has changed.
- Fixed not being able to see session history changes in non-Git directories or when the Git status is empty; file changes and diffs are restored from the session record and file-history backups.
- Fixed task notification messages in history polluting the chat; internal notifications are hidden when resuming a session, while agent task completed, failed or stopped states are kept.
- Fixed the session sidebar flashing "No sessions" on first load; it now shows a loading state first.
- Fixed old desktop sessions still carrying an expired provider id after provider configuration changes, causing CLI startup failures or unusable sessions; the id is now validated before startup and falls back to a valid configuration.
- Fixed desktop rewind sometimes rolling back to the wrong turn due to hidden messages or misaligned visible indexes; it now locates the target precisely by user message ID and verifies the original content.

## Other notes

- `.github/pull_request_template.md` adds PR summary, verification and risk confirmation items, and by default asks @dosubot to review from the angles of change scope, missing tests, docs impact, desktop startup risk and CLI core impact.
- `.gitignore` now includes `artifacts/quality-runs/`, keeping local quality gate reports out of commits.
- Removed tracked local plan and spec files under `docs/superpowers/`; they are local execution artifacts and are no longer committed with product code.
- PR quality gates do not call real models or live providers by default; real model baselines remain in local or controlled release gates that maintainers run explicitly.
- The release gate continues to run later provider and desktop smoke lanes even if one live baseline fails, and outputs a full pass/fail/skipped summary to show coverage across the whole matrix.
- WebSearch fallback currently requires you to configure a Tavily or Brave Search API key yourself; without a fallback key, non-Claude models will not be forced to expose an unusable native WebSearch.
- The GitHub Release body still comes from `release-notes/v0.2.0.md`, so the Markdown no longer has to be copied by hand.
