# Claude Code Haha v0.4.4

This is a stability and desktop experience patch release after `v0.4.3`. It focuses on fixing real-world problems in background tasks, Goal continuation, prewarm startup, provider/proxy, Trace, settings privacy, browser preview and Windows window behavior.

Compared with `v0.4.3`, this version keeps background Agent tasks visible after the foreground reply ends and reduces the noise of task notifications leaking back into the model or the desktop transcript; it also fixes session prewarm races, unintended prewarming of past sessions, CLI-only provider proxy, loopback proxy, MCP secret display, Trace deletion and provider preset updates.

## Highlights

- **More reliable background tasks and Goal continuation**: background tasks stay visible after the foreground turn completes, in a clearer background task drawer; Goal auto-continuation inserts a visible divider so multiple assistant turns no longer blend together; task-notification-only follow-ups no longer pollute the desktop transcript.
- **More stable startup, prewarm and session refresh**: fixed the race where the idle timer killed an active CLI when `prewarm_session` and `user_message` arrived almost simultaneously; viewing past sessions no longer triggers prewarm; the Electron sidecar waits until `/health` is truly ready before continuing; session list summaries are cached, lowering the chance of refresh timeouts with large histories.
- **More compatible provider/proxy pipeline**: CLI-only OpenAI-compatible providers start a lightweight standalone provider proxy and no longer depend on a fixed localhost server; loopback provider targets bypass the system proxy and Bun proxy fetch options; provider connectivity checks cover IPv4/IPv6 loopback; direct provider traces correctly record redacted headers.
- **Desktop workflow details completed**: the Settings tab, provider form saving, empty-session composer drafts, active turn timing, cache token usage, long title tooltips, the manual refresh button, browser preview navigation and the preview-agent edit bubble are all more stable.
- **Safer settings and diagnostics**: the MCP settings page masks sensitive command args, env and headers while keeping the original values on save; MCP server names support Unicode letters and digits; the Trace list adds local trace session deletion and makes clear that chat history is not deleted.

## Fixes

- Fixed the session prewarm idle timer killing an active user turn during the CLI startup blind window, leaving the desktop stuck on "running" (#865).
- Fixed viewing a past transcript wrongly triggering CLI prewarm; loading history no longer starts a new CLI (#880).
- Fixed the Anthropic/OAuth endpoint being prechecked before launch during first onboarding, contacting external services before sign-in or any model request (#859).
- Fixed the handling path that could produce `API Error: Stream ended without receiving any events` after stopping or interrupting.
- Fixed a set of issues with scheduled task timeouts, scheduled subprocess permission arguments, title generation auth and parallel tool card settlement (#809, #846, #847, #854, #889).
- Fixed cancel/double-submit races when saving the provider form, the Settings tab being lost on return, and empty-session composer drafts being lost when switching projects (#810, #811, #871).
- Fixed WebContentsView staying on the old file when the same session opened a new native browser preview target, and the preview-agent edit bubble overflowing the viewport for selections low on the page (#819, #879).
- Fixed lost active turn duration timing, an unstable lightweight duration line after completion, and queued follow-ups conflicting with the completion status line position (#813, #853).
- Fixed CLI-only OpenAI-compatible desktop providers depending on a fixed local server proxy, and loopback provider targets/connectivity checks wrongly going through the proxy in proxied environments (#845, #896).
- Fixed background sync Agent tool activity not using the unified parent-tagged events, missing fallback for incomplete tool-use streams, and structured local Agent terminal notifications leaking back into the model (#870, #884, #886).
- Fixed EnterPlanMode exposing internal model instructions, ExitPlanMode rejected tool cards showing an empty plan card, and the Windows frameless window drag hit area not refreshing after first show (#869, #874).
- Fixed manual refresh of the desktop session list possibly being disabled or spinning for a long time due to a pending background fetch (#893).
- Fixed a delayed FileReader callback for a pasted image re-polluting the composer after sending or switching sessions (#827).
- Fixed the Electron sidecar continuing startup after only a TCP accept without waiting for HTTP `/health` ok (#857).
- Fixed OpenAI-compatible sampling params being passed through too broadly by default, and missing GLM-5.2 context metadata (#860).
- Fixed long sidebar titles lacking a full tooltip (#885).
- Fixed MCP server names being restricted to ASCII; Unicode letters and digits are now supported, while spaces and separators are still rejected.
- Fixed sensitive args, env and headers leaking into visible UI/inputs on the MCP settings page.
- Fixed direct provider traces not persisting redacted headers when headers were passed via a `Request` input (#836).
- Fixed the live session header not counting cache read/write tokens (#842).
- Fixed Goal hook evaluator errors being treated as non-blocking hook errors, which stopped the goal loop early.
- Fixed Goal hook `preventContinuation` and `blockingError` returned separately being misread as an ordinary stop, which stopped the goal midway (#895).
- Fixed Goal continuation turns lacking a clear visual divider in session history and desktop restore (#901).
- Fixed outdated presets, model context windows and thinking capability declarations for Chinese providers.

## Features and Improvements

- The Trace list adds a delete entry that idempotently deletes local trace JSONL and clears the trace read cache; the confirmation dialog explains that chat history is not deleted (#868).
- Background task display is upgraded to an official-style background task drawer that keeps task progress after the foreground completes, and restored Agents no longer disappear when old completed items are cleaned up.
- Goal auto-continuation adds a `Goal continuing` local command divider that flows through server events, session history and desktop history restore.
- Provider settings JSON import supports cc-switch style model configuration: the main model is derived from `ANTHROPIC_MODEL` or the Sonnet fallback, and `*_MODEL_NAME` is treated as a display label.
- Provider presets update Chinese models and context window declarations, with related runtime/env, thinking and conversation-service test coverage.
- Session list summaries are cached by JSONL file mtime/size, lowering the cost of repeated scans for `/api/sessions?limit=400` in large history directories (#894).

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.4.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the Git tag `v0.4.4` and `release-notes/v0.4.4.md` must be strictly aligned.
- This version touches desktop, server, provider/runtime, agent-loop and native surfaces; before release, run at least `bun run scripts/release.ts 0.4.4 --dry` and `bun run verify`, and with real provider quota run `bun run quality:gate --mode release --allow-live --provider-model <provider:model[:label]>`.
- Additional smoke tests before release are recommended: the background Agent task drawer, Goal auto-continuation, task notification output suppression, opening past sessions, switching projects from an empty session, provider connectivity check, loopback provider, Trace deletion, MCP secrets redaction, native browser preview, Windows frameless dragging, first launch of the signed macOS DMG and auto-update metadata.
- To verify all-platform signed/notarized artifacts first, trigger the `Release Desktop` workflow manually and keep `draft=true`; the official release is still based on the commit for the `v0.4.4` tag and its GitHub Actions artifacts.

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.4-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.4-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.4-win-x64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.4-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.4-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.4-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.4-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If macOS signing and notarization pass verification, the first launch should go through the normal Gatekeeper flow directly.

If it still reports "is damaged" or "cannot verify the developer", the build may still be the unsigned fallback or the local quarantine state has not been cleared; run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.4-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.4-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.4-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
