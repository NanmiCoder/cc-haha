# Claude Code Haha v0.2.8

This release focuses on **the new /goal feature, the Portable / Windows desktop experience, runtime environment consistency, session recovery and chat interaction stability**.

Compared with `v0.2.7`, the most important change is the official addition of `/goal`: you can create a goal in the CLI, desktop app or WebUI, a running goal stays visible on desktop, and the completion result goes into the conversation history and persists after refreshing or resuming the session. This release also brings a batch of fixes previously scattered across worktrees or the remote main into the mainline: Windows terminals and portable storage become configurable and understandable; launching the desktop app from Finder / the Dock gets an environment closer to a real terminal; session, worktree and sidebar recovery are more reliable; and everyday issues with custom slash commands, unsent drafts, AskUserQuestion, multi-agent progress and results, batch-closing running tabs, Feishu onboarding and provider model mapping are addressed.

## Highlight

- **New /goal goal management**: `/goal` is now an official feature for creating goals, showing the running goal and recording the completion result; the completed state is persisted to the transcript via a Stop hook, the desktop app shows the running goal in a compact header, and completed goals appear back in the chat history.
- **Visual portable storage configuration**: Settings now explains where the current config directory comes from, lets you choose a portable data folder, and guides you through a controlled restart when needed, so you can understand and switch the data directory without relying on environment variables.
- **More reliable Windows terminal and sidecar**: Windows users can configure the built-in terminal startup shell / Bash path; the priority of the system fallback, portable Bash path and explicit startup shell is clearer, and the Windows x64 sidecar compatibility fix is restored.
- **Desktop child process environment matches the terminal**: desktop sessions, MCP stdio and scheduled tasks capture the user's login + interactive shell environment, reducing missing `npx`, Homebrew, nvm or custom PATH when launched from Finder / the Dock.
- **More stable session recovery and workflow state**: legacy Windows workdirs, stale worktrees, the macOS `/var` alias, sidebar project recovery and background task state all have clearer recovery paths.
- **Cleaner chat input and Agent display**: custom slash commands are no longer overwritten by live updates; unsent drafts persist across tabs; multi-question AskUserQuestion no longer mixes up answers; "Add to chat" follows the real selection more closely; Agent background progress is shown back inside the Agent card, and completion results prefer the readable report instead of exposing raw transport JSON.
- **Friendlier integration and configuration entries**: the unconfigured Feishu state shows the creation entry and required steps directly; empty provider model slots are normalized consistently in the UI and on the server, so empty `ANTHROPIC_DEFAULT_*` values never reach the runtime.

## Main updates

- Settings adds a clearer storage / portable mode section showing the source of the active config directory, and supports choosing a portable data folder in the Tauri desktop app.
- The Tauri native layer adds reading/writing and restart preparation for app mode / portable path / terminal config, so state is no longer opaque after switching the config directory.
- Windows terminal settings support a custom Bash path and desktop terminal startup shell, and block saving invalid paths.
- The Windows x64 sidecar build restores a low-instruction-set compatibility path, reducing startup failures on low-end Windows machines.
- Desktop child processes merge the user's shell environment at startup, covering desktop CLI sessions, scheduled tasks, MCP stdio and MCP preflight.
- Desktop update checks support system proxy and manual proxy settings, applying only to the app updater and never mixed with provider / model proxies.
- Added the `/goal` goal management entry, supporting creating goals, tracking the current goal state, and keeping completion results as part of the conversation history.
- The desktop `/goal` UI shows the running goal in a compact header strip and moves completed goals into the conversation flow, so goal state does not take up too much chat space.
- The `/goal` completed state is persisted via the Stop hook and the local command transcript, so the CLI, headless mode, desktop history and WebUI all see the same completion result.
- Added a local Web UI launch script that automatically avoids occupied ports and passes the actual backend URL to the Vite frontend.
- Agent / subagent result display keeps the terminal-side Markdown report; when there is no report, structured fallback and text-wrapped JSON are formatted into readable results too.
- The unconfigured Feishu settings state adds an OpenClaw creation entry and two-step setup hints, reducing getting stuck on first binding.

## Fixes

- Fixed unstable project or session recovery caused by legacy Windows session workdirs, stale worktrees and the macOS `/private/var` alias.
- Fixed a project not reappearing after being removed from the sidebar even though its sessions were not deleted.
- Fixed custom `.claude/commands` slash commands disappearing from the desktop command list after a CLI live update.
- Fixed unsent desktop prompts being lost after switching to Settings, Terminal or another tab.
- Fixed custom input and option state overwriting each other in multi-question AskUserQuestion.
- Fixed the "Add to chat" popover positioning by mouse location instead of the real selection, covering the selected text or leaving multiple popovers behind.
- Fixed desktop status hiding background work when an assistant turn had completed but background bash / tasks were still running.
- Fixed `/goal` completion results not being visible after refreshing or resuming a session, and running / completed goals taking duplicate space in the desktop UI.
- Fixed one-time worktree startup status text leaking into later Thinking / execution bubbles.
- Fixed local_agent / remote_agent background events during Agent tool calls being rendered as standalone transcript cards, causing duplicates and exposing internal types.
- Fixed Agent completion reports being overwritten by raw tool_result, and structured fallback / text-wrapped JSON showing as raw JSON in previews and result dialogs.
- Fixed type safety of Agent group result label formatting under strict TypeScript builds.
- Fixed batch-closing tabs bypassing the running-session confirmation, which could silently abandon running tasks.
- Fixed the notification plugin listener cleanup losing its `this` context, causing an unhandled rejection during browser shell cleanup.
- Fixed an out-of-bounds file path access risk in the Feishu adapter, and kept adapter session mappings cleaned up when unbinding / deleting sessions.
- Fixed empty model slots still reaching the runtime environment when the provider's main model was available but haiku / sonnet / opus were left blank.
- Fixed a timing issue in adapter coverage where the WsBridge test occasionally sent a message before observing the connection.
