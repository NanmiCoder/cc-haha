# Claude Code Haha v0.4.2

This is a stability and desktop experience patch release after `v0.4.1`. It focuses on fixing problems exposed in real use: desktop hangs, H5 remote access, Windows installation and window behavior, Trace observability, provider/runtime compatibility, and the built-in browser and generated artifact preview pipeline.

Compared with `v0.4.1`, this version adds drag-to-reorder for the provider list, an Auto-dream settings entry and plugin/Skill usage statistics in Activity; it also makes slow third-party providers, GPT5.5 relay caching, phone H5, queued input during an active turn and Trace diagnostics more stable.

## Highlights

- **More stable slow providers and long desktop tasks**: the desktop app no longer kills healthy streaming requests with a slow first byte using an overly short timeout, the non-streaming fallback state is shown in the chat status bar, and aborted API calls show up in Trace instead of staying pending forever, with particular attention to #766 and #773.
- **Queue input while a reply is in progress**: during an active turn you can keep submitting, steering, editing and deleting queued messages; once the CLI accepts them they are replayed into the transcript automatically, avoiding duplicate user bubbles from guided prompts or replay, fixing #755.
- **More stable H5 remote access**: the H5 token and port persist across restarts, the disconnect grace period is configurable, and locking the phone or switching apps no longer kills the running CLI; touch H5 fixes input zoom, keyboard overlap, long-press selection, invisible action buttons and safe-area handling, following up on #764, #767 and #780.
- **Better Trace and Activity observability**: Trace now shows tool call durations, session wall/model/tool timing, aborted API calls and more stable live updates; the Activity page adds plugin and Skill usage rankings and a more compact token summary, covering the diagnostic needs from #799 and #766.
- **Focused Windows desktop fixes**: fixed repeated install prompts and install directory selection in the Windows updater/installer, hidden CMD window flashes on exit, restored native window dragging and stopped the window from gradually growing while dragged, and fixed the Settings General toggle layout and the white screen when enabling system notifications, covering #801, #802, #770, #796, #788 and #791.
- **Smoother provider/runtime configuration**: the provider list supports drag-to-reorder with persisted official/custom provider order, an Auto-dream settings entry is added, and the OpenAI-compatible proxy handles the prompt cache key, stream usage and cached tokens in a way that better fits GPT5.5/relay providers, covering #753, #800 and #789.

## Fixes

- Fixed mapped Windows drive workspaces still being wrongly blocked in bypass mode after resolving to UNC; mapped drive paths proven to be inside the workspace can be written again, while sensitive paths and UNC writes outside the workspace still go through permission safety checks.
- Fixed the context percentage staying at the pre-compact value after a manual `/compact` or automatic compaction, or even showing `Request timed out after 30s` (#743).
- Unified token usage display between desktop and CLI, fixing the missing streaming token indicator on the first message, in-progress token counts not updating, and inconsistent formats across pages (#757).
- Widened the fetch window of the desktop sidebar session list, reducing the chance of observer/noisy sessions pushing real sessions out of the list (#759).
- Fixed issues with the built-in browser preview menu, file Open With, manually entered local HTML paths and the loopback web dev access policy; `127.0.0.1`, `localhost` and `::1` can bypass the H5 token for local development, while LAN/public access remains protected by H5 rules (#761).
- Fixed the MCP configuration page title implying "update", which misled users into thinking an update was running (#763).
- Fixed the H5 token/port not being fixed, QR codes and phone bookmarks breaking after restart, and the background CLI being force-killed 30 seconds after the client disconnected (#764, #767).
- Fixed the UI staying in running after slow third-party providers were killed early on desktop by the client timeout, stream watchdog or fallback chain; fallback state and abort trace records are also completed (#766).
- Fixed `~` paths not being expanded when clicking "Show in Explorer/Finder" for generated artifacts on Windows/macOS (#776).
- Fixed generated file chips and preview anchors guessing paths from model text and pointing at files that do not exist; they are now aligned with the turn's real changed files, making single-file `index.html`, artifacts outside the workspace and image replay deduplication more reliable.
- Fixed ExitPlanMode/plan mode approval showing only the raw permission request on desktop; it now shows a rendered plan preview and correctly forwards feedback and the permission response back to the CLI (#793).
- Fixed the prompt cache never hitting when OpenAI-compatible providers go through the Responses API via GPT5.5/third-party relays; requests strip the rotating billing attribution line, use a stable `prompt_cache_key`, and map `cached_tokens` back to Anthropic cache usage (#789).
- Fixed Markdown preview rendering problems when generated Mermaid flowchart labels contain HTML line breaks, braces or bracketed type text (#803).
- Fixed Windows settings page checkbox focus/reflow, a white screen when enabling system notifications, and stale native preview views not closing after leaving the session page (#788, #791).
- Fixed the renderer-side delta fallback repeatedly calling setPosition while dragging Windows frameless windows, which made the window grow or changed its bounds incorrectly (#770, #796).
- Fixed the Windows updater repeatedly prompting to install when using stale same-version metadata, a faked version fallback display, and the NSIS installer not allowing the install directory to be chosen (#801).
- Fixed multiple CMD windows possibly popping up from the Electron sidecar, taskkill, CLI and scheduled-task subprocesses when quitting on Windows (#802).
- Fixed missing tool call durations in Trace, live trace polling not noticing in-place call changes, detail section collapse state leaking across sessions, and aborted requests staying pending for a long time (#799, #766).
- Fixed the local macOS release/packaging script possibly exiting early when launching electron-builder through `bunx`; electron-builder is now launched through the installed Node CLI.

## Features and Improvements

- The provider settings page supports drag-to-reorder; official and custom providers share one ordering model, persisted via `providers.json`/`providerOrder` (#753).
- Settings adds an Auto-dream toggle with an explicit confirmation before enabling, reusing the CLI's existing background memory consolidation (#800).
- The Activity page adds aggregated historical plugin and Skill usage, showing Codex-style activity insights and rankings.
- In touch H5 environments `data-touch-h5` is set before first paint, so mobile fixes apply only to phone browsers and do not affect the desktop shell or desktop browsers (#780).
- New or changed text in desktop General settings, Trace, H5, provider, Activity and elsewhere is localized for all languages.
- The release workflow adds tag/version/release notes alignment checks and continues to use `release-notes/vX.Y.Z.md` as the GitHub Release body.

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.2.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the Git tag `v0.4.2` and `release-notes/v0.4.2.md` must be strictly aligned.
- This version touches desktop, server, provider/runtime, agent-loop, native and docs/release surfaces; before release, run at least `bun run verify`, and with real provider quota run `bun run quality:gate --mode release --allow-live --provider-model <provider:model[:label]>`.
- An additional real desktop smoke test before release is recommended: GPT5.5 provider, active-turn queued input, H5 phone access, Trace detail, Windows install/exit, Windows mapped drive, built-in browser HTML preview and generated artifact reveal.
- If this version is still not code signed for Apple / Windows, the system may require you to allow the first install manually once (see the installation notes below). Installing over the old version does not delete local data (`~/.claude`, `~/.claude/cc-haha` and custom portable data directories).

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.2-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.2-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.2-win-x64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.2-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.2-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.2-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.2-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If it reports "is damaged" or "cannot verify the developer" on first launch, run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.2-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.2-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.2-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
