# Claude Code Haha v0.5.0

This is a UI redesign release after `v0.4.11`. The desktop visuals are rebuilt according to the "Paper · Ink · Seal" design spec, a component library is extracted to replace native controls scattered across the codebase, the brand mark changes from a bitmap to a vector redrawn per theme, and following the system dark/light appearance is added. It also fixes a batch of issues: denying a tool aborting the whole turn, interrupted streams not retrying, parent MCP configuration not being deletable, and duplicate counting in usage statistics.

The version jumps directly from `0.4.11` to `0.5.0`: the bulk of this round is a wholesale replacement of the presentation layer rather than point fixes, and continuing to increment the patch number would understate the scope. Skipping versions does not affect in-app auto-update; `electron-updater` compares versions with semver, and `0.5.0` is newer than any `0.4.x`.

## Highlights

- **Full "Paper · Ink · Seal" UI redesign**: 6 themes (Pure White, Paper Ink, Warm Classic, Celadon, Ink Night, Ink Night Blue) using a two-layer token structure of source color swatches plus a single semantic mapping layer; headings use self-hosted Noto Serif SC Latin subsets, with CJK falling back to the system serif; corner radius, shadow and motion scales are finalized. The shell, zero state, active session, all composer popovers, skills marketplace, scheduled tasks, every settings section, Trace, the terminal and ⌘K have all been redone. Only the presentation layer changes; features, data contracts and interaction logic stay the same; the old `light` theme setting migrates automatically to `warm-classic`.
- **Desktop component library**: added a `components/ui` primitive layer (24 components) and a `components/composite` shared parts layer, replacing previously scattered native controls; of 362 native buttons only 22% were reused, icon buttons had 15 different corner radii and 12 sizes, 41% had no focus ring and 10 had no accessible name. Component reuse is now 75%; the remainder are elements that should not be componentized, such as `role="tab"`, `menuitem` and whole-row or whole-card click targets. Four gatekeeping tests check layer dependencies, token resolvability, AA contrast and caller counts.
- **Brand mark rebuilt as a vector**: the app icon is rebuilt from a 120KB bitmap into vector geometry that can be recolored per theme: the two Cs take the ink color, while the seal bar, cursor and star take vermilion. Every consumer drops parts by size: the star appears at 40px and above, the cursor at 24px and above, and the Cs and seal bar are always kept. The app icon itself stays one fixed piece of artwork (the Dock and taskbar are drawn by the system and do not know the in-app theme), while the in-app mark is a vector redrawn per theme.
- **Follow system dark/light appearance** (#1106): Settings → General adds a toggle. The system only reports dark/light while the app has 6 themes, so the palette picker is split by background into "Use in light mode" and "Use in dark mode" groups, each remembering its own preference. This also fixes the white flash on every launch: `index.html` previously hardcoded `data-theme="white"`, and the code that reads the saved theme only ran after the app bundle's dynamic import finished; now a synchronous inline script resolves the theme before any stylesheet is parsed, and Electron also presets the window background color from the cached appearance. New installs follow the system by default, while existing installs keep their fixed theme until the user turns this on.
- **Resizable sidebar**: an 8px drag handle on the right edge sets the width between 240–480px, persisted to localStorage; double-click returns to 300px and arrow keys fine-tune it. Dragging left stops at 240px, only collapses to a narrow rail past 180px, and only expands again past 200px on the way back; the 20px hysteresis avoids flickering open and closed from a shaky hand. The settings sidebar shrinks from 260px to 220px (200px would truncate the Japanese "コンピューター操作"; the measured threshold is 210px).
- **Run location consolidated into a single pill**: directory, branch and worktree were three buttons on a separate bar below the composer; they are now merged into one pill in the toolbar row, alongside "+" and the model selector. It is editable while the session is a draft and becomes read-only after the first message is sent, staying in the same place. Branch names are truncated keeping the end (`…use-native-on-main` rather than `feature/comp…`), because the end is what distinguishes them.
- **Infinite scroll in the skills marketplace**: paging changes from a "Load more" button to a scroll observer that triggers 400px early, with placeholder cards while loading; the number of first-screen skeleton cards is computed from available space instead of a fixed 6. Load failures have their own inline message and retry, no longer clear the whole catalog, and do not auto-retry into the same failure.
- **Pet sprite sheets of any size**: importing animated pets previously required a file of exactly 1536×2288 with 88 seamlessly laid out cells; no image model outputs that size, so this path always ended at size validation, and the "AI-generated full animation" card was a dead entry hardcoded as `disabled`. Now an 8×9 sprite sheet of any size is automatically sliced, scaled and mirrored in the browser to generate leftward running, and rows are reused to fill out 11 action sets. Sheets that are already 1536×2288 pass through unchanged without resampling. Added white-background detection: sheets with less than 5% transparent pixels are rejected with an explanation; previously such images were silently imported and rendered on the desktop as a rectangle.
- **`.agents/skills` cross-client convention** (#1093): recognizes the `.agents/skills` directory convention shared by multiple AI clients.

## Fixes

- Fixed dialog backgrounds being see-through. `.glass-panel` put the semi-transparent fill and the blur in the same rule, so frosted glass only appeared when both worked; when `backdrop-filter` does not apply, CSS raises no error and just skips the declaration, leaving the 0.84 fill on its own and letting 16% of the page content show through clearly. Dialogs now use `--color-surface-dialog`, which is opaque by construction and does not rely on blur at all.
- Fixed the whole turn silently ending after denying a tool permission (#1051). The desktop's denial was returned to the CLI with `interrupt: true`, which triggered an abort; the denial was written into the transcript but no follow-up request was made, so the model neither learned about the denial nor got a chance to respond. The CLI's own denial message is now sent, so the model is asked again and replies. ExitPlanMode has the opposite semantics (rejecting a plan means "keep planning"), so it uses a separate message.
- Fixed streams not retrying after being interrupted. The `The socket connection was closed unexpectedly` seen with Grok is a bare Error thrown by Bun when reading a response body the peer has RST, and it slipped through all three recovery paths: `withRetry` only wrapped stream creation, not consumption; `isRetryableStreamError` required an APIError with `api_error` in the SSE body; and the desktop injected a switch disabling the non-streaming fallback. Transport-level error codes (ECONNRESET/EPIPE and so on) are now detected along the cause chain and the stream is rebuilt. Retries are bound by the same side-effect boundary as the watchdog: once a tool_use block has completed or server-side tool activity has started, the disconnect is reported faithfully instead of replayed.
- Fixed four deviations in Grok Responses requests (each verified against the official CLI with real requests). A `tool_choice` naming a specific tool was previously translated into Chat Completions syntax, and the Responses endpoint returned 422, failing every request that named a tool; session-level identity reuse via `prompt_cache_key` and `x-grok-conv-id` is also added, avoiding billing the whole prefix again every turn.
- Fixed servers declared in a parent directory's `.mcp.json` not being deletable (#1107). Reads walk up from the current directory inheriting every `.mcp.json`, but deletion only looked at the current directory's own file, so these servers appeared deletable and clicking delete reported "An unknown error occurred". This also fixes a credential leak: adding a server rebuilt the entire config file and wrote back values with `${VAR}` expanded; in testing, `"Bearer ${MY_MCP_TOKEN}"` was written out as a plaintext secret, in a file that is usually committed.
- Fixed thinking blocks being split into multiple segments while a background agent was working (#1108). Background agent tool activity is re-emitted as ordinary events with a `parentToolUseId` and lands at the end of the message array, while the merge check for streaming thinking blocks looked at whether the tail of the array was a thinking block; the tail became a child tool call, so every subsequent chunk started a new bubble. These bubbled-up child messages are now skipped when merging.
- Fixed tasks deleted by `TaskUpdate` staying in the activity panel (#1101). `deleted` is a delete action, not a status, and the CLI removes the task file directly; the activity panel parsed it as a status, fell through to the `pending` default and kept it on the panel.
- Fixed usage statistics counting one assistant reply multiple times. Claude Code writes JSONL line by line per content block, and every line repeats the full `usage` object, which both statistics paths were summing; in this repository a real message spanning 52 lines with 50.8K tokens was counted as 2.65M. Also fixed: the cost field was previously dead code that was never assigned; unknown models are no longer billed at Claude prices (12.7% of tokens came from third-party providers); "Longest task" was previously measured as the time between first and last event, so sessions resumed overnight counted the whole night, with readings of 436 and 1137 hours observed; it now accumulates effective working time from gaps of 30 minutes or less; transcripts of workflow subagents were previously never indexed.
- Fixed the session header taking up too much height. The redesigned header stacked an untruncated 22px title above the metadata row, so long titles wrapped and pushed the body down; the title is now truncated to one line and the metadata moved to a line below it, measured to shrink from 123.5px to 66.75px, with the full title kept in the hover tooltip.
- Fixed a dragged pet being unable to sit against the macOS menu bar. macOS passes the frame of a shown window to `constrainFrameRect:toScreen:` for rewriting, and any y above the work area is silently pulled back to the top edge; testing showed only the top edge is constrained, while left, right and bottom always worked. `enableLargerThanScreen` is the only switch that skips this method. This also fixes position drift after restart: the window was created before the renderer reported the mascot area, so clamping the whole window on restore opened it one padding height too low.
- Fixed a dragged pet on Windows being clipped, unable to sit against the display edge, and not keeping its position after restart (#1099, #1104).
- Fixed pasted images rendering as generic file cards. After pasted files were unified onto the native path, every attachment was marked `type: 'file'` with no preview source, while reopening the tab displayed them correctly from the transcript's inline image blocks, so live display and restored display diverged. The display source for image attachments is now resolved by extension, while the WebSocket payload still only carries the path.
- Fixed Skill frontmatter being rendered as Markdown. The closing `---` of the YAML block was parsed as a setext heading marker, so the whole frontmatter rendered as one huge bold `<h2>` above the document. It is now split out and laid out as structured rows.
- Fixed plugin reload failures still reporting success. The half where changes were written to disk but the runtime reload failed was previously completely silent and indistinguishable from a normal success message.
- Fixed all loopback requests being rejected when the desktop process token was present. Previously, once the desktop shell injected the token, a loopback address no longer counted as grounds for trust, and the system browser can never get that token, so the Grok OAuth success page, `/preview-fs` links and plain curl all returned 401. Loopback is now independently trusted again, and the token is only required on the `/api/h5-access` control plane (other programs on the same machine must not be able to publish the user's session to the network). This also closes an older CSRF hole: `if (!origin) return true` also accepted cross-site subresource loads; Fetch Metadata is now used to distinguish real navigations from subresources.
- Fixed handling when `taskkill` is missing on Windows (#1091), and the `electron:dev` launcher being unusable on Windows.
- Fixed inconsistent resolution of same-named skills across multiple root directories, and several deviations in `.agents` source marking, doctor checks and list safety.

## Features and Improvements

- Controls for session metadata, the attachment gallery, the image lightbox and in-page find gain accessible names and keyboard operation; the lightbox supports arrow keys and wraps around at both ends, and hides the arrows for a single image.
- 48 previously hardcoded user-visible strings gain translation keys in 5 languages (en / zh / zh-TW / jp / kr), including a whole block of hardcoded Chinese under `browser/` and hardcoded English in several places. `TranslationKey` is derived from `en.ts`, so a missing key is a compile error rather than a blank at runtime.
- Terminal colors change from 20 hardcoded hex values to reading per-theme `--color-terminal-*` tokens.
- Dropdown menus gain listbox semantics, arrow key navigation and focus return; 21 handwritten outside-click handlers are unified into `useDismissable`, using `pointerdown` by default, since `mousedown` is unreliable on touch screens, which is exactly why "tapping outside does not close the menu" on H5.
- Added a development-only component gallery (`/gallery.html`) that renders every primitive under three themes. Unit tests cannot tell whether a token resolves to a readable color, whether an overlay covers what it should, or whether an entrance animation actually plays; the gallery itself found three defects that existed despite all tests passing.
- The docs site was rebuilt with React, and the landing page copy was rewritten.
- The component library's usage rules, layering rationale and audit evidence are recorded in `desktop/src/components/AGENTS.md` and `docs/component-library-plan.md`.

## Verification

- The quality gate was run locally in release mode, and all 13 non-live lanes passed: Policy 127 tests, Desktop 271 files / 3331 passed 1 skipped, Server 227 files / 2447 tests, Adapters 406 tests, Provider contract 18 groups, Chat contract all groups, Native (sidecar compile + Electron checks + directory packaging smoke), Docs 80 pages / 302 links and images, Persistence upgrade, Quarantine (0 entries) and the Baseline case catalog.
- The Coverage gate passed 5/5 suites, with Desktop React line coverage at 90.19%. On the first run this gate failed; the root cause was that `nativeAppearance.test.ts` cases did not pass an isolated env: `check:coverage` runs in a sandbox with `CLAUDE_CONFIG_DIR` set, and that variable takes precedence over `app.getPath('home')`, collapsing the cache paths that should have been independent per case into one file, so one case read a value written by another. This was fixed by explicitly passing an isolated env, matching the existing approach in `windows.test.ts`, and verified once with and once without the variable set. This was a test isolation defect and does not affect product behavior; the `Release Desktop` workflow does not run this gate, while the `pr-quality` workflow does.
- Not executed, and not counted as passed: 6 baseline cases and 1 provider live/proxy smoke require real provider credentials and were not run locally; `desktop-package-smoke` requires locally signed release artifacts and is covered by CI's `Verify packaged app structure` and `Verify macOS launch policy`; this round of UI rework did not get a screen-by-screen walkthrough on a real machine; the real `v0.4.11 -> v0.5.0` auto-update path must be verified after the Release is published.
- The evidence above only covers the local candidate build and tests, and is not equivalent to end-to-end verification of official signing, notarization or cross-platform installation.

## Notes

- The GitHub Release body uses `release-notes/v0.5.0.md` as its only source.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, the version, the Git tag `v0.5.0` and this file must be strictly aligned.
- Jumping from `0.4.11` to `0.5.0` does not affect auto-update. `electron-updater` uses semver comparison (`semver.gt`) rather than string comparison, and update metadata comes from the repository's latest Release regardless of whether version numbers are consecutive. `0.5.0` has no prerelease suffix, so it stays on the stable channel and metadata file names are unchanged.
- The `Release Desktop` workflow builds x64 / ARM64 installers for macOS, Windows and Linux, and publishes the Release only after complete assets and updater metadata pass verification.
- The auto-update verification path is the official `v0.4.11 -> v0.5.0`. After publishing, check `latest-mac.yml`, `latest.yml`, `latest-linux.yml` and `latest-linux-arm64.yml`.
- Official public macOS releases depend on signing and notarization secrets; without Windows signing configured, the app can still be installed and auto-updated but may show a SmartScreen warning.
- This is a wholesale replacement of the presentation layer with no changes to features or data contracts; existing sessions, provider configuration, Skills, Agents, memory and custom data directories need no migration. The old `light` theme setting migrates automatically to `warm-classic`.
- The component gallery (`/gallery.html`) is only reachable under `bun run dev` and is not included in the production bundle, since Vite's build entry is only `index.html`.

Download for your system and CPU architecture from the Assets at the bottom of this page:

### macOS

Double-click the DMG and drag the app into Applications. Officially signed and notarized builds should pass the normal Gatekeeper flow directly.

### Windows

Double-click the `.exe` to install. Run it as the current user; do not use **Run as administrator**. Fully quit the app before upgrading in place; if the installer reports related processes still running, close them as prompted and try again. If SmartScreen warns on an unsigned build, choose **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.5.0-linux-x86_64.AppImage
./Claude-Code-Haha-0.5.0-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.5.0-linux-amd64.deb
```

On ARM64 machines, use the matching `linux-arm64` files.
