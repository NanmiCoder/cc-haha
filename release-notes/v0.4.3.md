# Claude Code Haha v0.4.3

This is a patch release after `v0.4.2` covering the desktop experience, provider/runtime, agent-loop and release signing verification. It focuses on fixing problems exposed in real use: context window declarations, streaming request stability, background subagent activity display, workspace preview, session search and terminal shortcuts.

Compared with `v0.4.2`, this version adds global full-text session search, tabbed Workbench panels and a terminal clipboard shortcut toggle, and completes the macOS Developer ID signing/notarization release pipeline. For 0.4.3, it is recommended to first generate all-platform artifacts through the GitHub Actions Draft Release path to verify the new macOS signing and Gatekeeper behavior, then decide whether to publish publicly.

## Highlights

- **macOS signed release pipeline enters verification**: the official release workflow prechecks the macOS certificate, Apple ID, app-specific password and Team ID; when secrets are complete it builds signed/notarized DMG/ZIP files and also runs a Gatekeeper package smoke test. When the workflow is triggered manually, `draft` is on by default, suitable for generating a draft release and all-platform assets first.
- **More accurate provider/runtime context declarations**: provider settings support declaring 1M context and a custom context window, Anthropic providers include Tool Search by default, and new sessions prefer the provider's main model, reducing mismatches between model capabilities and UI state.
- **More stable streaming requests**: the first-token wait respects the request timeout, the overall stream caps the maximum duration of free-trickling providers, and recoverable transient tool-call errors mid-stream are retried instead of failing the turn outright.
- **Smoother desktop workflows**: added global full-text session search, Workbench panels can expand into tabs, terminal settings support clipboard shortcuts, and tool write/edit progress, pending JSON input, workspace diff preview and output card links are more reliable.
- **More complete background agents and chat recovery**: background subagent tool activity streams to the desktop; token usage is restored after reopening a session, slash-command breadcrumbs are hidden when restoring history, and the pending tool spinner stops correctly after an interrupt.

## Fixes

- Fixed provider settings being unable to declare 1M context and the server not correctly passing through the provider context window (#814, #830).
- Fixed Anthropic providers not enabling Tool Search by default, leaving related tool capability declarations missing (#823).
- Fixed new sessions not preferring the provider's main model (#818).
- Fixed token usage being lost after reopening a session, and slash-command breadcrumbs leaking into chat bubbles when restoring past sessions (#820, #833).
- Fixed background subagent tool activity not streaming to the desktop in real time; the desktop now shows background agent tool progress (#829).
- Fixed streaming boundaries for slow or misbehaving providers: the first-token wait, overall stream duration and transient mid-stream tool-call errors are now handled by clearer rules (#766, #826).
- Fixed MessageList still being pulled back to the bottom by thinking/autoscroll while scrolling manually during a reply (#727).
- Fixed incomplete handling of the Memory empty state and tool autoscroll state (#728, #729).
- Fixed pending tool JSON input not wrapping, invisible tool write/edit progress, and the pending spinner not stopping after an interrupt (#703, #707, #712, #751).
- Fixed workspace diff preview not refreshing to the latest workspace state, and the workspace navigator not collapsing automatically during preview (#706, #709, #724).
- Fixed log links in output cards being treated as openable targets and navigating somewhere they should not (#714).
- Fixed unstable docked terminal size, and terminal copy/paste shortcuts lacking a desktop host capability toggle (#708, #837).
- Fixed the release workflow and update metadata merge pipeline, supporting signed Electron release updates and completing standard update metadata validation.

## Features and Improvements

- Added a global full-text session search entry that searches past sessions, message content and related metadata, with quick opening of results from the sidebar.
- Workbench panels support tabs, so workspace, terminal and other panels can expand into a wider workspace layout (#730).
- Terminal settings add clipboard shortcut configuration, and the Electron host exposes the matching capability, reducing cross-platform terminal copy/paste conflicts (#837).
- The provider settings page completes the UI, types and persistence for context window, Tool Search defaults and main model selection (#814, #818, #823, #830).
- Release docs add desktop installation and auto-update instructions; the release workflow validates complete assets and standard update metadata, and supports Gatekeeper checks for signed macOS builds.

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.3.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the GitHub Release tag `v0.4.3` and `release-notes/v0.4.3.md` must be strictly aligned.
- A draft release is recommended this time: after pushing the 0.4.3 version commit to `main`, trigger the `Release Desktop` workflow manually and keep `draft=true`; do not use `git push origin main --tags` for the public tag release path first.
- The draft workflow first builds all-platform artifacts for macOS ARM64, macOS x64, Windows x64, Linux x64 and Linux ARM64, then creates a Draft Release. After confirming macOS signing, notarization, the Gatekeeper smoke test and auto-update metadata, decide whether to publish the release.
- Before release, run at least `bun run scripts/release.ts 0.4.3 --dry` and `bun run verify`; if provider credentials/quota are available, also run `bun run quality:gate --mode release --allow-live --provider-model <provider:model[:label]>`.
- This version touches release, native, desktop, server, provider/runtime and agent-loop surfaces; additional smoke tests are recommended: first launch of the signed macOS DMG, auto-update metadata, global search, Workbench tabs, provider context window, Tool Search defaults, background subagent tool activity, terminal shortcuts and slow provider streams.

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.3-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.3-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.3-win-x64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.3-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.3-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.3-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.3-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If macOS signing and notarization for this Draft Release pass verification, the first launch should go through the normal Gatekeeper flow directly.

If it still reports "is damaged" or "cannot verify the developer", the build may still be the unsigned fallback or the local quarantine state has not been cleared; run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.3-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.3-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.3-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
