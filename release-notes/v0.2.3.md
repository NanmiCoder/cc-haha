# Claude Code Haha v0.2.3

This release focuses on **H5 phone access, desktop usage statistics, reply language control and Computer Use configuration stability**.

Compared with `v0.2.2`, the biggest change is taking desktop H5 browser access from an experiment to a complete, configurable, authenticated pipeline usable on phones: you can enable H5 in desktop settings, manage the access token and allowed origins, and use the chat interface in a phone browser over the LAN or through a reverse proxy. The desktop app also adds a local token usage activity view, the reply language can be set directly in General settings, and Computer Use gains a custom Python interpreter and reliable virtual environment rebuilds.

The "Fixes" section of this release covers only problems users may actually have hit in already released versions, such as Computer Use failing to detect Python on Windows / conda, chat scrolling and context menu glitches, generated titles containing internal markers, context usage above 100%, an unreliable scheduled task launch entry point, and compatibility issues with third-party providers missing the usage field. Work on H5 tokens, CORS, mobile layout and LAN access was part of building the new feature and is described with the features.

## Highlight

- **H5 phone browser access takes shape**: desktop settings add an H5 toggle, a one-time token, an origin allowlist and an access URL, supporting both phone access on the LAN and reverse proxy setups.
- **Reworked phone chat experience**: at phone width H5 switches to a chat-first layout, the sidebar becomes a drawer, and the model, permission, project and worktree selectors use mobile bottom sheets.
- **Stronger remote access security boundary**: H5 REST, WebSocket, CORS and health checks all go through H5-aware auth, and the remote token never leaks into local browser sessions.
- **Token usage activity view**: Settings adds local Claude Code CLI transcript usage statistics, showing recent sessions, messages, tools, model tokens and daily activity.
- **Visual reply language setting**: General settings add a reply language selector that writes the CLI `language` setting in `~/.claude/settings.json`.
- **More control over Computer Use Python**: you can specify a custom Python interpreter, fixing failed auto-detection on Windows / conda and similar environments, and the matching virtual environment is reliably rebuilt after switching interpreters.

## Main updates

- Added H5 access controls: in desktop General settings you can enable H5, generate / copy a token, configure allowed origins and get the browser access URL.
- Remote H5 access goes through server authentication and CORS: API, proxy, WebSocket, health responses and preflight requests all recognize the H5 token and origin restrictions, so the desktop API is never exposed directly.
- The packaged desktop sidecar can bind to a LAN address while the desktop control URL stays on loopback, so a phone on the same Wi-Fi can open the H5 page.
- The browser startup flow adds an H5 credential entry: non-local backends require an H5 token, while local Tauri and localhost development paths keep their existing behavior; the remote token never carries over to later local browser sessions.
- The H5 phone layout is chat-first: desktop-only workspace and terminal panels are hidden on mobile, the sidebar is collapsed by default, the composer and selectors use touch-friendly layouts, and the header is compressed to leave more room for chat.
- Added a shared `MobileBottomSheet` interaction for phone selectors such as model, permission, project, branch and worktree, since desktop popovers are unusable on narrow screens.
- H5 LAN access prefers the currently auto-detected LAN URL, avoiding stale addresses after the packaged app restarts or the port changes; an explicitly configured public reverse proxy address is still kept.
- The empty-session composer and workspace diff display on H5 phones are adapted for narrow screens; generated code diffs scroll horizontally for long lines instead of being squeezed into phone width.
- Added a desktop Token usage / Activity page that aggregates session, message, tool, model token, subagent token and daily activity data from local CLI transcripts.
- General settings add a reply language selector that writes preset languages to the CLI language setting, so later sessions reply in that language by default.
- Computer Use settings add a custom Python interpreter path; backend environment checks and venv creation use the specified interpreter first, and a marker file records which interpreter a venv belongs to, avoiding misjudged conda / pyenv / venv wrapper paths.
- Scheduled task result summaries now use the shared Markdown renderer, so links, lists, bold, code and similar formatting no longer show as raw Markdown.
- The README home page now highlights the desktop app as the main entry point, with updated screenshots of the desktop workflow, Token usage, H5 access and worktree changes, while keeping source launch instructions.

## Fixes

- Fixed unreliable automatic Python discovery for Computer Use on Windows / conda and similar environments (issue #331); you can now specify the Python path manually in settings.
- Fixed the old venv state still being reused after switching the Computer Use custom Python; the actual selected interpreter path is now recorded and dependencies are rebuilt when the interpreter changes.
- Fixed the scroll position being lost when switching session tabs or reading history; each session's scroll context is kept, and a jump-to-bottom button appears while auto-follow is paused.
- Fixed the `jump to latest` button briefly flashing during streaming because of programmatic scroll events.
- Fixed the context menu not appearing when right-clicking a session in the sidebar; it also opens correctly with the sidebar collapsed.
- Fixed generated session titles sometimes containing internal XML / slash-command metadata; desktop display and server generation share the same title cleanup logic.
- Fixed context token usage showing above 100% for some large-window models; the current context total is now clamped to the model's context window.
- Fixed AskUserQuestion not respecting the CLI `multiSelect` flag; only explicitly multi-select questions allow multiple choices, and the response is sent back to the session that produced the prompt.
- Fixed transcript, side query or cost statistics errors when a custom provider or Anthropic-compatible fallback response lacks the usage field.
- Fixed `/agents` and the TUI agent wizard still reading stale cached definitions after creating, editing or deleting a custom agent.
- Fixed scheduled task child processes possibly inheriting a stale `CLAUDE_CODE_ENTRYPOINT`; the default task launch entry point now reliably uses the SDK CLI.
- Fixed continuing an already materialized worktree session repeatedly showing the worktree startup state and passing worktree creation arguments again.
- Fixed the project context chip being left-aligned in compact mode.

## Docs and tests

- Added `docs/desktop/06-h5-access.md`, explaining H5 opt-in settings, token usage, CORS origins, LAN access and reverse proxy recommendations.
- Added H5 access design and implementation plan docs, recording the security boundary and implementation breakdown for opt-in browser access.
- Updated the Chinese and English READMEs so new users see desktop downloads, core workflows and the latest screenshots first.
- Added regression tests for the H5 access service, auth, API, CORS, browser bootstrap, mobile layout, settings store, Computer Use Python, Activity stats, session title, AskUserQuestion, MessageList, TaskRunsPanel and more.
- The desktop Token usage changes passed `bun run check:desktop` and `bun run check:server`; the H5 mobile changes passed desktop lint, build, server H5 auth tests, a LAN URL smoke test and a phone viewport smoke test; the Computer Use Python changes passed backend and desktop settings tests.

## Other notes

- The GitHub Release body still comes from `release-notes/v0.2.3.md`, so the Markdown no longer has to be copied by hand.
- H5 is an explicitly enabled personal / team browser access feature, not a public multi-tenant authentication system; only configure trusted origins and keep the generated token safe.
- The release workflow no longer runs the release preflight quality gate on tag publish; maintainers should still run local `bun run verify` or the release gate as needed before releasing.
- When using H5 from a phone, prefer the same LAN address; reverse proxy deployments must preserve WebSocket upgrade and the path prefix.

## Installation

If the app reports "is damaged" or "cannot verify the developer" on first launch, run:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```
