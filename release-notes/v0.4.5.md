# Claude Code Haha v0.4.5

This is a patch release after `v0.4.4` covering stability, provider/proxy compatibility, desktop workflows and Windows ARM64. It focuses on fixing problems exposed in model connections, permission modes, first-turn provider activation, past session timestamps, sidecar memory, browser preview zoom, Markdown safety and release smoke tests.

Compared with `v0.4.4`, this version makes OpenAI-compatible providers use a more explicit direct proxy mode by default, so the system proxy or sidecar proxy environment no longer affects model connections; it also completes reasoning effort pass-through, an experimental beta toggle, a default session permission setting, quick switching with `/model`, Skill command history restore, Windows ARM64 startup and package-smoke detection.

## Highlights

- **More stable provider/proxy connections**: provider requests use direct proxy mode by default and inherit the system proxy only when System proxy is explicitly selected; when a third-party API returns a `model` that differs from the requested model ID, the context window is no longer misreported as `200000`; reasoning effort is correctly passed through to the proxy transform.
- **More accurate permissions and first-turn behavior**: added a default session permission mode setting; `bypassPermissions` skips approvals that can be skipped while keeping explicit denies and tools that require interaction; after a clean install, the first question after adding a provider applies the active provider runtime before prewarm and the user message.
- **Past sessions and list performance keep improving**: past session ordering is no longer refreshed to "just updated" by metadata-only writes; session times use a more stable month-day-hour-minute format; non-Git projects are no longer slowed down by git-info probing for new sessions; recent projects and session list loading paths reduce repeated scans further.
- **Cleaner desktop chat details**: the completed turn duration system line is no longer persisted to the transcript; `/model` opens the model selector; Skill commands typed by the user are kept in restore, WebSocket replay and search; automatic Dream task cards no longer add noise to chat content.
- **Preview, layout and security completed**: the built-in browser adds zoom/scale controls synced to the Electron WebContentsView; the workspace panel can shrink to the right again; Markdown rendering blocks `<style>` tags and inline styles from being injected into the global UI.
- **More reliable Windows ARM64 and release smoke**: Windows ARM64 desktop startup, sidecar timeout diagnostics, the release workflow and package-smoke detection are completed; the desktop live smoke waits for the restored project chip before typing, lowering the chance of wrongly creating a default home session.

## Fixes

- Fixed provider connections in `v0.4.4` still being affected by the system proxy or sidecar proxy environment; default provider requests now use direct proxy mode, with network settings tests for provider connectivity and the OpenAI-compatible proxy (#953, #896).
- Fixed reasoning effort not being passed as a model call parameter; the OpenAI Chat/Responses proxy transform now passes reasoning effort (#905).
- Fixed the first turn after a clean install, when a provider was added and a question asked without clicking Test, possibly not applying the active provider runtime and thinking forever (#844).
- Fixed abnormal session context window display when the `model` in a third-party API response differs from the requested `modelId`.
- Fixed approvals still being required in the highest-permission skip mode; `bypassPermissions` now skips approval asks while keeping constraints for explicit denies and tools that require user interaction (#910).
- Fixed the `/model` slash command not opening the model selector (#909).
- Fixed Skill commands typed by the user being hidden in session restore, WebSocket replay or session search (#926).
- Fixed automatic Dream task lifecycle cards entering the chat transcript and task status staying running (#887).
- Fixed completed turn duration messages being persisted as system transcript lines.
- Fixed the header/sidebar keeping the old message count after `/clear`.
- Fixed `<style>` tags or inline styles in model output being able to affect desktop Markdown rendering styles (#904).
- Fixed an Invalid pages parameter error loop when the model wrongly passed the `pages` parameter while reading non-PDF files (#928).
- Fixed high memory pressure in the Claude Code sidecar with large transcripts, reducing repeated hydration of large session files on trace/message polling paths (#933).
- Fixed git-info probing possibly slowing down new sessions or opening an external editor when the project path contains Chinese characters or the project is not a Git repository (#908).
- Fixed metadata-only writes when viewing a past session refreshing its "last updated" time to just now (#951).
- Fixed unstable time display for update checks and message actions; a clearer month-day-hour-minute format is now used throughout.
- Fixed slow loading of the recent projects list within a session, and invalidated the recent project cache when sessions change.
- Fixed new sessions that were never run leaving an invalid untitled session behind after closing.
- Fixed the workspace panel only being draggable larger to the left and not shrinkable to the right (#940).
- Fixed desktop startup errors on Windows 11 ARM64, and completed ARM64 sidecar/native files and unpacked package-smoke detection (#954).

## Features and Improvements

- Added a default session permission mode setting in General settings; new desktop chat sessions use this default while keeping per-session overrides.
- Provider settings add a `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` compatibility toggle that disables experimental beta headers for third-party API channels and isolates stale parent env (#929).
- The built-in browser adds per-session zoom/scale controls, synced to the preview bridge, Electron WebContentsView, screenshots and annotation coordinates (#952).
- Release/package smoke covers Windows ARM64 artifact detection, current-platform package smoke and release workflow metadata boundaries, lowering the risk of missed platform artifacts before release.
- Command metadata handling is unified across session restore, search and WebSocket replay, continuing to hide abnormal command breadcrumbs while keeping Skill commands the user actually typed.
- Cross-surface paths such as trace/session message signatures, the recent project cache and desktop smoke gain regression protection against post-release semantic conflicts.

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.5.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the Git tag `v0.4.5` and `release-notes/v0.4.5.md` must be strictly aligned.
- This version touches desktop, server, provider/runtime, agent-loop, native and release surfaces; before release, run at least `bun run scripts/release.ts 0.4.5 --dry` and `bun run verify`, and with real provider quota run `bun run quality:gate --mode release --allow-live --provider-model <provider:model[:label]>`.
- Additional smoke tests before release are recommended: OpenAI-compatible provider direct and System proxy modes, reasoning effort, the experimental beta toggle, first provider question after a clean install, default permission mode, bypass permission, `/model`, Skill command restore, the Dream task drawer, Read on non-PDF files, past session times, the recent projects list, browser zoom, Markdown style injection, Windows ARM64 startup and first launch of the signed macOS DMG.
- To verify all-platform signed/notarized artifacts first, trigger the `Release Desktop` workflow manually and keep `draft=true`; the official release is still based on the commit for the `v0.4.5` tag and its GitHub Actions artifacts.

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.5-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.5-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.5-win-x64.exe` |
| Windows ARM64 | `Claude-Code-Haha-0.4.5-win-arm64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.5-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.5-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.5-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.5-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If macOS signing and notarization pass verification, the first launch should go through the normal Gatekeeper flow directly.

If it still reports "is damaged" or "cannot verify the developer", the build may still be the unsigned fallback or the local quarantine state has not been cleared; run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.5-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.5-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.5-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
