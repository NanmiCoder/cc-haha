# Claude Code Haha v0.2.6

This release focuses on **restoring secure H5 phone access, desktop session management, file mention search and desktop experience details**.

Compared with the temporary open access in `v0.2.5`, this release puts H5/LAN access back behind explicit opt-in and a token pairing model, and moves the entry to its own settings page for easy phone QR scanning. On the desktop side it adds batch session deletion, a pure white theme, consistent @ file search, and fixes for several chat input and display issues.

## Highlight

- **Secure H5 access restored**: H5/LAN access again requires explicit local opt-in, a QR link carries a token that is shown only once, and remote API, proxy and WebSocket are no longer exposed.
- **Clearer H5 entry**: Settings adds a standalone H5 Access page with enable confirmation, QR generation and access URL copy, and the README shows the real phone experience.
- **Batch session management**: the desktop sidebar adds a batch management mode with select all, group selection, Shift range selection and deleting selected sessions.
- **@ file search aligned with the CLI**: desktop file mentions now use git-first search that respects project ignore rules, reducing noise from `node_modules`, build output and similar.
- **Desktop polish**: added a pure white theme, refreshed the brand icon, and fixed long URLs breaking the chat layout and drafts leaking across tabs.

## Main updates

- The H5 access policy distinguishes local trusted requests, internal SDK requests and remote browser requests; with H5 off, remote capability endpoints fail by default, and with H5 on, they require the H5 token.
- The H5 control plane stays local-desktop-only; remote browsers cannot enable or change H5 access configuration themselves.
- Browser startup validates the shape of the `/health` response, so the Vite SPA fallback is not mistaken for an available backend.
- Settings moves H5 Access out of General and completes token generation, QR, URL copy, error messages and public URL configuration.
- Sidebar batch management keeps a clear "Delete selected" path, removes the easily misunderstood clean-up-by-days shortcut, and improves visual distinction of consecutive selected rows.
- @ file mention search uses tracked files, untracked files with exclude-standard, and a ripgrep fallback in non-git directories; directory candidates are derived from these results too.
- File mention menu path display and insertion behavior are further aligned with the CLI, reducing ambiguity from showing only file names.
- The pure white theme covers more desktop surfaces, so warm classic colors no longer leak into the neutral white workspace.
- Desktop and docs assets are refreshed with the new logo, and the app icon no longer shows a double background inside the desktop app.

## Fixes

- Fixed long URLs or long Markdown links pushing user message bubbles out of the chat column.
- Fixed unsent drafts and attachment state leaking between multiple session tabs.
- Fixed insufficiently compatible usage conversion when the OpenAI-compatible Responses API omits or returns different usage fields.
- Fixed access misclassification caused by unclear boundaries between H5 remote origins, CORS, SDK routes and local loopback calls.
- Fixed unintuitive errors such as JSON parse failures from later API calls after H5 startup fails.

## Verification

- Added and updated regression tests for H5 access policy, auth, CORS, Settings and desktop runtime.
- Added and updated tests for session batch delete, sidebar batch mode, ChatInput, UserMessage, FileSearchMenu, the filesystem API and OpenAI-compatible usage fallback.
- Related commits passed `bun run check:server`, `bun run check:desktop`, `bun run check:coverage`, `bun run verify`, the desktop build, the docs build, and browser smoke tests for H5, batch management, draft isolation and icon display.

## Other notes

- The GitHub Release body still comes from `release-notes/v0.2.6.md`, so the Markdown does not have to be copied by hand.
- H5 is a browser access entry for individuals or trusted teams, not a public multi-tenant sign-in system; only enable it on trusted networks with trusted origins, and keep the generated token safe.

