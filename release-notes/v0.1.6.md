# Claude Code Haha v0.1.6

This release focuses on desktop extension management, the MCP experience, command-line install paths and session stability.

Compared with `v0.1.5`, it adds real in-app entry points for MCP, plugins and command-based install configuration, and fixes provider/model selection leaking across sessions, MCP cold start, plugin detail refresh, broken formatting in streamed messages and incomplete rewind recovery.

## New features

- Added a real terminal in the desktop app for running host commands directly, used to install plugins, Skills and MCP dependencies and to handle extension setup that requires the command line.
- Added a bundled CLI launcher: after installation you can use the desktop-bundled CLI from an external terminal via `claude-haha`, without hunting for the executable.
- Added desktop MCP management:
  - View, create, edit, enable/disable, delete and reconnect MCP servers from the settings page.
  - Distinguish user-level MCP servers from those exposed by plugins.
  - See reconnect progress and runtime status directly on the detail page.
- Added local Slash Command entry points in the chat composer: `/mcp`, `/plugin`, `/skills` and similar jump straight to the matching desktop management view.
- Added a desktop plugin management API and UI, so plugins, Skills, Agents and similar capabilities can be browsed and opened from the settings page in one place.
- Improved session rewind: rewind restores not only the conversation state but also the matching file checkpoints, lowering the cost of recovering from mistakes.
- Improved provider/model selection: sessions now reliably use the provider, model and runtime configuration you selected, and are no longer unexpectedly overridden by global Claude settings.

## Fixes

- Fixed MCP tools sometimes not being ready for the first desktop conversation, leaving the first request with incomplete capabilities.
- Fixed the MCP list being blocked by live health checks; the list now shows immediately and updates status asynchronously.
- Fixed provider/model selection inheriting global settings and leaking across sessions, and aligned the built-in provider presets with currently available models.
- Fixed inconsistent React Hook order that could occur when refreshing or reloading plugin details.
- Fixed task progress updates during streaming breaking Markdown layout.
- Fixed assistant text on desktop being split into multiple non-contiguous bubbles; replies now stay in a single message.
- Fixed state misalignment during desktop history loading and reconnects, reducing lost output or output bound to the wrong session after reconnecting.
- Fixed missing confirmation for some destructive actions; deleting providers, plugin associations, sessions and similar now asks for confirmation first.
- Fixed Computer Use settings compatibility with Python 3.8.
- Fixed stale content and ghosting that could remain after resizing the Ink main interface.
- Fixed reduced close button visibility after moving tabs by drag.
- Fixed the app icon appearing square on older macOS, and the desktop icon preview not matching the actual packaged icon.
- Improved update prompts: no more misleading `0%` progress, and "Remind me later" is remembered per version.

## Other notes

- Desktop install and configuration entry points have moved from the old Install Center to the more reliable host terminal, the `claude-haha` CLI and the matching settings pages.
- Windows installers and release artifact names were cleaned up to reduce confusion during installation.
- The docs publishing workflow now includes a lockfile and Node version constraint, so the docs workflow no longer fails on `npm ci` after dependency updates.
- The GitHub Release body still comes from `release-notes/v0.1.6.md`, so the Markdown no longer has to be copied by hand.

## Installation

### macOS

If the app reports "is damaged" or "cannot verify the developer" on first launch, run:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```
