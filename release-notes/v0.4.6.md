# Claude Code Haha v0.4.6

This is a desktop feature and stability release after `v0.4.5`. It adds a skills marketplace and a session activity panel, and addresses the TeamoRouter provider, the update flow, the portable data directory, the terminal, output style localization, browser zoom, high-DPI preview and provider stalled stream diagnostics.

Compared with `v0.4.5`, this version lets users discover, preview, install and manage third-party skills directly on desktop; it also gathers in-session tasks, background tasks, SubAgents and team activity into a right-hand activity panel, reducing noise in the main chat and making multi-Agent workflows more visible.

## Highlights

- **Skills marketplace launched**: a new desktop skills marketplace aggregates ClawHub and SkillHub, with search, filters, pagination, details, file preview, install confirmation, uninstall and installed-state detection.
- **More conservative skill installation**: the marketplace install flow adds risk labels, scan summaries, source status, a disclaimer and blocking for unconfirmable risks, so incomplete or high-risk upstream results are never presented as safe to install.
- **Session activity panel**: a new right-hand activity panel shows tasks, background tasks, SubAgents, team activity and sources in one place; SubAgent runs can be opened in their own detail page.
- **Clearer Agent workflows**: SubAgent activity rows gain local avatars and status, tool call groups are collapsed by default, and manual expand/collapse state is kept during streaming updates.
- **More stable updates and official releases**: public releases stay in draft until all-platform installers, blockmaps and `latest*.yml` update metadata are uploaded and verified, lowering the risk of auto-update picking up incomplete assets.
- **Provider and platform completeness**: added a TeamoRouter provider preset; a watchdog adds diagnostics when provider streaming responses stall; browser zoom, high-DPI coordinates and Windows/macOS/Linux release assets continue to converge.

## Fixes

- Fixed repeated update checks possibly clearing a pending update during the update check flow; if restart-to-install does not make the desktop app quit, the UI returns to an actionable state (#797).
- Fixed the official GitHub Release possibly going public before updater assets were fully uploaded; a draft is now created first and only un-drafted after release assets and standard update metadata are fully verified.
- Fixed best-effort writes such as window state possibly failing after changing the data storage location and causing permission errors to pop up repeatedly; write failures are now caught and reported in the settings status (#949).
- Fixed the Terminal settings page triggering terminal runtime startup twice, causing two command prompt lines, and added teardown protection for stale async starts (#964, #967).
- Fixed built-in option names and descriptions in General -> Output style not being localized to the current language (#966).
- Fixed unstable coordinates and interactive areas for built-in browser zoom/scale on high-DPI displays; the zoom controls now float at the bottom right of the preview area so the native WebContentsView no longer covers them (#952).
- Fixed the lack of clear diagnostics when a provider streaming response stalls midway, adding a staged watchdog and more stable desktop WebSocket error codes.
- Hardened Telegram adapter command handling and desktop navigation guards, reducing risk from malformed input or external navigation.
- Fixed several edge cases in skills marketplace search, detail preview, fallback caching, theme colors, loading states and card risk text.

## Features and Improvements

- Added a skills marketplace API and desktop Market page, with ClawHub / SkillHub aggregation, source health status, remote details, file content preview and paginated loading.
- Added a skills marketplace install service that shows a risk summary and confirmation dialog before installing and detects local installed state afterwards.
- The skills marketplace adds a third-party skill disclaimer, security badges, deterministic skill avatars, multilingual text and dark theme support.
- Added a session activity panel and activity model that organize Todo/task summaries, background tasks, SubAgent notifications, team members and sources into scannable side information.
- Added a SubAgent run detail page and related API, allowing SubAgent output, status and token/duration information to be opened from the activity panel.
- Added a TeamoRouter provider preset with default model mapping to `claude-opus-4-8`, `claude-sonnet-5` and `claude-haiku-4-5`, and added a TeamoRouter entry to the README sponsors section (#994).
- The release workflow continues to verify installers, blockmaps and updater metadata for macOS ARM64/x64, Windows x64/ARM64 and Linux x64/ARM64.
- Windows signing remains a non-blocking warning; unsigned Windows installers can still update, but users may see a SmartScreen warning.
- Non-draft public macOS releases now require signing and notarization secrets; when missing, the release is blocked so auto-update and Gatekeeper never get unqualified official artifacts.

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.6.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the Git tag `v0.4.6` and `release-notes/v0.4.6.md` must be strictly aligned.
- For official releases, the `Release Desktop` workflow checks that the tag matches the `desktop/package.json` version and loads `release-notes/v0.4.6.md`.
- Auto-update depends on complete installers, blockmaps and standard updater metadata in the GitHub Release: `latest-mac.yml`, `latest.yml`, `latest-linux.yml` and `latest-linux-arm64.yml`.
- Official public macOS releases require signing and notarization secrets; without them only draft/test artifacts can be kept. Windows signing does not block releases, but unsigned installers trigger a SmartScreen warning.
- If the desktop app does not quit and restart automatically after downloading an update, restart the app manually to finish installing.
- Before release, run at least `bun run scripts/release.ts 0.4.6 --dry` and `bun run verify`; once GitHub Actions hosted runners are available again, trigger a draft `Release Desktop` manually to verify all-platform assets first.

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.6-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.6-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.6-win-x64.exe` |
| Windows ARM64 | `Claude-Code-Haha-0.4.6-win-arm64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.6-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.6-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.6-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.6-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If macOS signing and notarization pass verification, the first launch should go through the normal Gatekeeper flow directly.

If it still reports "is damaged" or "cannot verify the developer", the build may still be the unsigned fallback or the local quarantine state has not been cleared; run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.6-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.6-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.6-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
