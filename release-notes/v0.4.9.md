# Claude Code Haha v0.4.9

This is a local data, search and network compatibility release after `v0.4.8`. It adds a SQLite local index, search across unexpanded workspace files, bundled cross-platform ripgrep and actions to open local attachments, and fixes local proxy authentication for OpenAI-compatible Providers, dynamic system proxy routing, H5 touch interaction and multi-line comments in file preview.

Compared with `v0.4.8`, this version projects sessions, activity statistics, scheduled task run records, Trace and searchable content into a rebuildable local database to reduce the cost of repeatedly scanning many files. The original JSON / JSONL files remain the source of truth; when the index is corrupted or unavailable, reads fall back to the files, and the index can be safely rebuilt in Settings → Diagnostics.

## Highlights

- **SQLite local index**: the session list, global search, activity statistics, scheduled task run records and Trace use a rebuildable local projection to speed up reads; after startup it keeps aligning with source files, and the file fallback path remains when the index is unavailable.
- **Full workspace file search**: the file panel can search directories that have not been expanded or loaded yet, so you no longer need to expand the tree first; results can still be previewed and added to the chat context.
- **Bundled cross-platform ripgrep**: desktop installers ship ripgrep for x64 / ARM64 on macOS, Windows and Linux, so users no longer need to install `rg` separately to use these search features.
- **Dynamic system proxy routing**: desktop AI sessions, OAuth, Provider requests and adapters use the current system proxy rules per target address, supporting direct, HTTP(S) and SOCKS routes and no longer pinning a stale startup-time proxy result for the whole run.
- **Better attachments and file review**: local attachments in chat can be opened with the system default app or the "Open with" menu; file preview supports holding Shift to select consecutive lines and bringing a whole-range comment back to the chat.
- **Better H5 touch experience**: on phones, message actions are always visible, key composer buttons are larger, and the layout of the sidebar, model selector, safe areas and soft keyboard viewport is improved.

## Fixes

- Fixed OpenAI-compatible local API / vLLM Providers possibly returning HTTP 401 continuously after upgrading to `v0.4.8`, because the desktop proxy authentication environment was not passed correctly (#1025).
- Fixed workspace files only being searchable after their directory was expanded; the server now searches the real workspace directly and reports clear states for missing, out-of-bounds and oversized results (#1023).
- Fixed file and session search being unavailable in packaged desktop builds without ripgrep, and brought binary, license and release artifact verification into the offline build flow (#923).
- Fixed the system proxy being resolved only once at startup for a single address, which made model connections, OAuth and Provider requests fail when proxy rules changed or different targets needed different routes (#953).
- Fixed fork, copy and other message actions on H5 phones only appearing on hover, as well as small composer buttons, a crowded sidebar and the soft keyboard covering content (#1020).
- Fixed file preview only allowing comments on a single line; you can now Shift-select multiple consecutive lines on the same side, keeping accurate line numbers, references and composer focus (#1004).
- Fixed global search with fast typing or a Chinese IME possibly letting old requests overwrite new results, leaving a stale loading state, or arrow keys landing on invalid results.
- Fixed sessions, scheduled tasks, teams, Trace and activity statistics possibly being briefly missing while the local index is being built or when a source is corrupted; related reads now wait for the projection, recover automatically or fall back to source files.
- Fixed past sessions still in the source directory not being reliably restored to the list after restarting the desktop app, and added index status, degradation reasons and a rebuild entry (#1016).

## Features and Improvements

- Added a derived database `cc-haha/db/index-v1.sqlite` covering session metadata and content, activity statistics, scheduled task run records, team sessions and Trace; supports incremental appends, file rewrite detection, deletion sync, migrations and corruption recovery.
- The diagnostics page adds a local index status panel showing build status, indexed sources, degraded sources, database / WAL size, last update time and error codes, with a confirmed rebuild option.
- Global search now uses the content index and supports cancelling stale requests, Chinese IME composition and per-session match previews; file search is still available while the index is building or degraded.
- Workspace file search uses the bundled ripgrep, with cross-platform executable preparation, offline license staging, sidecar packaging and release artifact smoke checks.
- Local attachments in chat gain direct open and an "Open with" dropdown, reusing the configured external editor or system default app; a failure message is shown when the file has been moved or deleted.
- H5 adds more stable viewport height, bottom safe area and soft keyboard state handling for touch devices, avoiding misclassifying desktop touch devices as phone layouts.
- The system proxy bridge resolves Electron proxy rules per target address and cleans up connections when the desktop service stops or restarts; model POST requests that cannot be safely replayed are never resent across proxy rules.
- The local index adds consistency, parity, migration, recovery and performance acceptance tests; the index database is always treated as disposable derived data and never replaces the user's source session and settings files.

## Notes

- The GitHub Release body still comes from `release-notes/v0.4.9.md`.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, `desktop/package.json`, the Git tag `v0.4.9` and `release-notes/v0.4.9.md` must be strictly aligned.
- For official releases, the `Release Desktop` workflow checks that the tag matches the `desktop/package.json` version and loads `release-notes/v0.4.9.md`.
- Auto-update depends on complete installers, blockmaps and standard updater metadata in the GitHub Release: `latest-mac.yml`, `latest.yml`, `latest-linux.yml` and `latest-linux-arm64.yml`.
- Official public macOS releases require signing and notarization secrets; without them only draft/test artifacts can be kept. Windows signing does not block releases, but unsigned installers trigger a SmartScreen warning.
- The local index only stores rebuildable derived data. Rebuilding or deleting the index never deletes original conversations, settings, Skills, memory, scheduled tasks or Trace source files; the file fallback is still available when the index is degraded.
- Desktop installers now bundle ripgrep. The CLI or a source development environment can still use the system `rg`, but official desktop search no longer depends on users installing it manually.
- Before release, run at least `bun run scripts/release.ts 0.4.9 --dry` and `bun run check:impact`; before the official tag, run `bun run verify` and a real `v0.4.8 -> v0.4.9` auto-update smoke test, with particular attention to past session restore, index rebuild, full workspace search, the system proxy and opening local attachments.

## Installation

Download the file for your system and CPU architecture from the Assets at the bottom of this page:

| Platform | File |
|------|------|
| macOS Apple Silicon(M series) | `Claude-Code-Haha-0.4.9-mac-arm64.dmg` |
| macOS Intel | `Claude-Code-Haha-0.4.9-mac-x64.dmg` |
| Windows x64 | `Claude-Code-Haha-0.4.9-win-x64.exe` |
| Windows ARM64 | `Claude-Code-Haha-0.4.9-win-arm64.exe` |
| Linux x64 | `Claude-Code-Haha-0.4.9-linux-x86_64.AppImage` or `Claude-Code-Haha-0.4.9-linux-amd64.deb` |
| Linux ARM64 | `Claude-Code-Haha-0.4.9-linux-arm64.AppImage` or `Claude-Code-Haha-0.4.9-linux-arm64.deb` |

### macOS

Double-click the DMG and drag the app into Applications. If macOS signing and notarization pass verification, the first launch should go through the normal Gatekeeper flow directly.

If it still reports "is damaged" or "cannot verify the developer", the build may still be the unsigned fallback or the local quarantine state has not been cleared; run in Terminal:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```

You can also click "Open Anyway" in System Settings → Privacy & Security.

### Windows

Double-click the `.exe` to install. If SmartScreen warns, click **More info** → **Run anyway**. Before removing the old version, the installer checks for data that needs to be recovered; if it detects an old version still running or a data directory it cannot safely assess, it keeps the old version and the original data and asks you to resolve it and try again. If the installer says it is running with too many privileges, just double-click it; do not use **Run as administrator**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.9-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.9-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.9-linux-amd64.deb
```

On ARM64 machines, replace the file name with `...-linux-arm64.AppImage` / `...-linux-arm64.deb`.
