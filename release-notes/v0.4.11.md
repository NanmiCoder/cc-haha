# Claude Code Haha v0.4.11

This is a desktop experience and Agent workflow release after `v0.4.10`. It adds interactive desktop pets, full desktop Agent management and per-Agent model and thinking effort configuration, and updates the official Claude model lineup. It also continues fixing task status, live SubAgent details, attachment restore, Provider creation, context estimation and Windows desktop recovery.

Compared with `v0.4.10`, this version makes background tasks and Agent configuration easier to observe, adjust and reuse: pets reflect the current task status in a standalone floating window, Agents can be managed at user or project scope, and each role can have its own model, effort and tools. Attachment content is kept after a session is restored, and task and subagent run state syncs to the desktop more promptly.

## Highlights

- **Interactive desktop pets**: added a native Electron transparent floating window with 4 built-in characters: Dada, Huhu, Bubu and Huihui; pets switch animations for working, waiting for input, failed and idle states, can expand active tasks, and clicking returns you to the matching session.
- **Local custom pets**: import a transparent PNG / WebP to make a lightly animated pet, or import a `1536×2288` v2 frame-by-frame sprite sheet; size, animation toggle and task panel display are adjustable, and the whole import happens locally without calling the current chat model.
- **Full desktop Agent management**: the settings page lets you browse Agents from built-in, user, project, plugin and policy sources along with their override relationships, and create, edit or delete user-level and project-level Agents.
- **Per-Agent model and effort**: each custom Agent can inherit or specify Fable, Opus, Sonnet, Haiku or a custom model ID, a thinking effort from `low` to `max`, and its available tools; the configuration is wired into Agent definitions, runs, restore and team execution (#1062).
- **Updated official Claude model lineup**: desktop and CLI add and recognize Fable 5, Opus 4.8, Sonnet 5 and Haiku 4.5, with display names, 1M context, reasoning effort and Provider environment mapping. Actual availability still depends on account access and Provider support.
- **More observable tasks and SubAgents**: running SubAgents can be opened immediately with new records streaming in; Task V2 completion state, concurrent updates and transient polling failures are reflected more reliably on desktop (#1075, #1077).

## Fixes

- Fixed context usage estimates disappearing when some Providers return empty or all-zero usage; the running model anchor is kept and estimation falls back to the local transcript, without mistaking the estimate for cost statistics (#1063).
- Fixed user messages possibly appearing twice after server replay when the first message carried images or files; Windows paths, UUID-prefixed uploaded files and inline images are supported (#1069).
- Fixed a normal interruption being misreported as an execution failure after denying a tool permission; the current turn now ends correctly and returns to a state where you can keep typing (#1070).
- Fixed tasks that had completed not updating their status promptly, stale requests overwriting newer state, and the task list flashing empty on transient polling failures (#1075).
- Fixed running SubAgent details staying on "starting" for a long time, so the execution could only be seen after it ended; run records and tool calls now refresh continuously (#1077).
- Fixed the "Add provider" button not working when the Provider presets endpoint was temporarily unavailable; common presets now ship with the desktop app, and the editable Custom entry is kept (#1078).
- Strengthened recovery and error isolation for Windows white screens, unexpected Renderer exits, proxy connection resets, and terminal and IM WebSocket lifecycles; the main window attempts limited recovery, and a visible error is kept for unrecoverable startup failures (#1064, #1065, #1071).
- Fixed file, directory and PDF attachments being reduced to bare paths and losing their original context after fully quitting the desktop app or restoring a session; external feedback sharing still filters attachment records and content.
- Fixed the pet task card being clipped by the native window shape on Windows, the close button being covered by the transparent hit area, and the pet not staying on top after restart.
- Fixed Agent files still being blocked by optional hot reload after they were saved, project Agents possibly being written to the outer repository when a nested Git repository was added at runtime, and stale refresh results overwriting newer project state.
- Fixed Session, Task, Scheduled and other endpoints possibly timing out together when local HTTP connections were reused after a long idle period on Windows; request cancellation and task polling resource cleanup are also completed.
- The Kimi Code preset is upgraded to K3: using the Coding API, the `k3` model, 262K context and API Key authentication, with required thinking, effort and max effort capabilities.

## Features and Improvements

- Desktop pets support drag to reposition, click interaction, eye tracking, right-click to close and window position restore; the task panel is collapsed by default and the count badge expands recent active sessions.
- Custom pet import adds a localized file picker and clear error messages for format, size, file size, duplicate IDs, corrupted images and storage failures.
- The Agent list shows source, active/overridden state, model, thinking effort, tool scope and system prompt; built-in, plugin and policy sources stay read-only.
- The Agent editor supports choosing a project directory, reads the actually available tools from the current runtime, lets you search and check them by category, and keeps rule input such as MCP, custom tools and `Bash(git:*)`.
- After an Agent configuration is saved, the current session's components refresh; a refresh failure does not roll back the saved definition and offers a retry prompt.
- The model selector merges the official catalog, the current Provider configuration and runtime role models, keeping custom model mappings for third-party Providers.
- Session state and task projections add cancellation, out-of-order and transient failure protection, reducing state regressions when switching sessions quickly or with many concurrent requests.
- The Electron build adds contract checks for sidecar startup, Renderer recovery, pet IPC, packaged output idle and cross-platform artifacts.

- The current merge candidate passed the desktop, server, provider-contract, chat-contract, adapters, native, persistence-upgrade and coverage gates: Desktop 2450 passed, 1 skipped; Server 2281 passed; Adapters 406 passed; Coverage 5/5 groups, 0 failed.
- Electron native verification included 312 tests, a sidecar compile smoke, a production build, macOS arm64 directory packaging and a current package smoke; this evidence only proves the local candidate build and artifact structure, and is not equivalent to official signing, notarization or cross-platform install E2E.
- Existing manual records on an isolated Windows 11 machine cover real DeepSeek / MiniMax conversations, attachment restore, multimodal input, live SubAgent details, Task V2, Renderer recovery, long-idle local connections, custom pet import and the pet task panel; some pet dragging/multi-monitor cases, real model and effort after Agent hot reload, and IM/H5 fault injection have not been fully executed.
- The official `v0.4.10 -> v0.4.11` auto-update and hands-on verification of Windows/Linux installers generated from the `v0.4.11` tag have not been executed yet, nor has the full live-provider combination test. Unexecuted items are not counted as passed.
- Two extreme connection edge cases still needing follow-up hardening have been identified: a CONNECTING WebSocket handshake that never completes, and sidecar health check responses that keep trickling small amounts of output. This version therefore does not claim to fully eliminate all connection leaks or startup hangs.

## Notes

- The GitHub Release body uses `release-notes/v0.4.11.md` as its only source.
- The desktop release version comes from `desktop/package.json`; the root `package.json` still keeps `999.0.0-local` for local development. When releasing, the version, the Git tag `v0.4.11` and this file must be strictly aligned.
- The `Release Desktop` workflow builds x64 / ARM64 installers for macOS, Windows and Linux, and publishes the Release only after complete assets and updater metadata pass verification.
- The auto-update verification path is the official `v0.4.10 -> v0.4.11`. After publishing, check `latest-mac.yml`, `latest.yml`, `latest-linux.yml` and `latest-linux-arm64.yml`.
- Official public macOS releases depend on signing and notarization secrets; without Windows signing configured, the app can still be installed and auto-updated but may show a SmartScreen warning.
- Desktop pets are an Electron desktop feature and do not run in H5; single-image import provides lightweight local animation, not AI frame-by-frame animation generation.
- Whether an Agent's effort fully takes effect depends on the chosen model and Provider; unsupported combinations may be lowered or ignored.

### macOS

Double-click the DMG and drag the app into Applications. Officially signed and notarized builds should pass the normal Gatekeeper flow directly.

### Windows

Double-click the `.exe` to install. Run it as the current user; do not use **Run as administrator**. Fully quit the app before upgrading in place; if the installer reports related processes still running, close them as prompted and try again. If SmartScreen warns on an unsigned build, choose **More info** → **Run anyway**.

### Linux

AppImage:

```bash
chmod +x Claude-Code-Haha-0.4.11-linux-x86_64.AppImage
./Claude-Code-Haha-0.4.11-linux-x86_64.AppImage
```

deb:

```bash
sudo apt install ./Claude-Code-Haha-0.4.11-linux-amd64.deb
```

On ARM64 machines, use the matching `linux-arm64` files.
