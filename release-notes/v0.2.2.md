# Claude Code Haha v0.2.2

This release focuses on **repository workflows, Worktree isolation, macOS notification stability and desktop runtime robustness**.

Compared with `v0.2.1`, the biggest change is making the desktop's "repository awareness" real: from the repository launch context bar and isolated Worktree launches to aligning desktop session identity with CLI worktrees, the desktop app can now start and label sessions more safely and accurately across multiple branches and worktrees. macOS notification scheduling, provider runtime isolation, scheduled tasks and Computer Use stability also received focused fixes.

## Highlight

- **Desktop repository workflow takes shape**: the launch context bar shows repository and branch/worktree selection in one place, with worktree isolation protection to avoid conflicts from concurrent multi-branch work.
- **Worktree session identity alignment**: the desktop session badge now reads from the native worktree identity first and then recovers from CLI transcript state, keeping sessions accurately linked to their code branch.
- **Stable macOS notification architecture**: notification calls moved from the invoke thread to the main queue, and build artifact signing identity is kept stable, eliminating random macOS notification failures.
- **Safer provider runtime**: Bearer providers no longer inherit local API Key environment variables, and each desktop session maintains its own provider runtime so sessions no longer contaminate each other.
- **Better Computer Use and scheduled tasks**: the Computer Use toggle is more stable, and scheduled tasks are correctly routed through the desktop sidecar with support for their own provider runtime configuration.

## Main updates

- Added a desktop repository launch context bar: empty chat tabs show the repository path, a branch/worktree selector and a one-click launch button, so the working context is explicit before the first message.
- Desktop branch launches are now protected by worktree isolation, avoiding conflicts when sessions for different branches are started concurrently in the same working directory.
- Desktop sessions are aligned with CLI worktree identity: the session badge reads native worktree information first and recovers from transcript state before the CLI finishes initializing, keeping the badge consistent across restarts.
- The built-in workflow agent graduates from internal experiment, so users can use workflow orchestration directly.
- Added a Computer Use opt-out: users can opt out of the bundled Computer Use package in settings and manage desktop automation dependencies as needed.
- Desktop notifications gain session routing: permission requests, task notifications and long-task replies now navigate precisely to the target session instead of opening a generic entry.
- Scheduled tasks can now specify their own provider runtime and no longer depend on the global provider setting when they run.
- Stronger quality gates: the PR quality verification flow can run itself, and gate results are observable and archived, improving confidence before release.

## Fixes

- Fixed Bearer providers inheriting local environment variables such as `ANTHROPIC_API_KEY`; Bearer providers now strictly use their own configured token and no longer unexpectedly pass through the local key.
- Fixed the desktop provider runtime being shared across sessions and contaminating them; each session now maintains its own provider runtime instance.
- Fixed macOS notification calls running off the main thread and failing randomly; notification calls are now scheduled on the main queue, and dispatch no longer blocks the invoke thread.
- Fixed unstable signing identity of macOS build artifacts across builds, which occasionally broke notification permission.
- Fixed the desktop Computer Use toggle being unstable in the task modal (it could reset unexpectedly after expanding/collapsing).
- Fixed CLI restarts triggered by configuration changes being misread as a new user message turn.
- Fixed a runtime explicitly selected at desktop launch being overwritten on some paths; a manually selected runtime now stays stable for the whole session.
- Fixed scheduled tasks not being routed through the desktop sidecar, which prevented them from running correctly in some configurations.
- Fixed UI details in the repository launch context bar: launch chips are more compact, the bar no longer overflows a single line with long content, and empty sessions show the bar correctly.
- Fixed desktop session tab titles not updating while a session is running.
- Fixed desktop UI state diverging from actual CLI state in local development builds, which made debugging difficult.
- Fixed IM chats still trying to reuse a desktop session after it was deleted, leaving IM messages unanswered; IM channels now check session validity and rebuild the binding.
- Fixed multiple instances of the desktop app possibly running at once; single instance is now enforced and a new launch activates the existing window.
- Fixed crashes during upgrade caused by leftover old persistence state, and added a safe Doctor recovery path for failed upgrades.
- Fixed occasional formatting problems in auto-generated session titles (extra quotes or unexpected characters).
- Fixed terminal tab error messages not staying visible when startup fails.
- Fixed newly activated desktop tabs sometimes not scrolling into view.
- Fixed ordinary folder paths being misdetected as a "repository problem warning"; path detection is now stricter.
- Fixed desktop session streaming state not being isolated when switching sessions, causing loading states to leak across sessions.
- Fixed the model selector in the task modal being clipped by its container so the dropdown was not fully visible.
- Fixed custom provider thinking settings being reset after a session reload.
- Fixed tool call parsing errors in the local proxy when handling real provider responses.

## Tests

- Added tests for waiting on the desktop repository launch ready state, ensuring worktree launch does not report success before the CLI is ready.
- Quality gate results are now written as structured artifacts, so CI and maintainers can trace gate execution history.

## Other notes

- Worktree launch mode can now be switched directly in the UI without editing configuration by hand.
- The GitHub Release body still comes from `release-notes/v0.2.2.md`, so the Markdown no longer has to be copied by hand.
- The Bearer provider auth token isolation fix is a **security improvement**: after upgrading, your local API Key will no longer be accidentally forwarded to third-party provider endpoints.
- If the app fails to start or shows a persistent white screen after upgrading, first use the desktop Doctor/recovery entry to handle regenerable local UI state; do not manually delete `~/.claude` or `~/.claude/cc-haha/`, to avoid losing Provider, OAuth, plugin, skill or session configuration.

## Installation

### macOS

If the app reports "is damaged" or "cannot verify the developer" on first launch, run:

```bash
xattr -cr /Applications/Claude\ Code\ Haha.app
```
