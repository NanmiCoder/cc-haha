# Claude Code Haha v0.2.1

This release focuses on IM integration, desktop notifications, context usage tracking and desktop runtime stability.

Compared with `v0.2.0`, the biggest change is making the desktop's external collaboration channels real: WeChat and DingTalk become first-class IM channels, mobile permission approval is smoother and the IM adapter sidecars are more stable. Desktop system notifications, diagnostic export, context usage and terminal working directories also received focused improvements.

This release also fixes a batch of issues most likely to be hit during pre-release manual testing: invisible WeChat replies, DingTalk unbind not clearing credentials, IM permission approval being awkward on phones, leftover Telegram sidecars preventing messages from arriving, desktop context usage dropping after a reply, misleading loading on empty sessions, and macOS notification permission appearing to succeed without real system notifications.

## Highlight

- IM integration becomes usable: WeChat and DingTalk are first-class IM channels, and pairing, permission approval and default project behavior are further unified across Feishu, Telegram, WeChat and DingTalk.
- More stable IM sidecars: each IM platform runs in its own sidecar, and stale adapters are cleaned up before startup, reducing Telegram long polling being hijacked by an old process.
- More trustworthy desktop notifications: macOS notifications now use a native UserNotifications bridge, so permission, test notifications and foreground display can all be truly verified.
- Context usage closer to the real session: `/context`, the desktop composer and the offline transcript fallback share one counting method, so usage no longer drops after a reply.
- Easier diagnosis of errors and startup failures: CLI startup failures, runtime exits and desktop API errors keep more useful redacted context.

## Main updates

- Added a WeChat IM adapter: QR code binding, pairing codes, text messages, image / file candidate extraction, reply sending, typing status and permission approval.
- Added a DingTalk IM adapter: Stream integration, QR code registration, AI Card streaming output, permission card templates, and a text authorization fallback when no template is available.
- The IM integration settings page now has configuration entries, pairing management, default project and Chinese/English text for Feishu, WeChat, DingTalk and Telegram.
- IM permission approval is friendlier on mobile: a single pending request can be answered with a short allow / always / deny reply, while concurrent requests still keep the requestId to avoid ambiguity.
- Each IM platform now runs as its own sidecar process, so Telegram, Feishu, WeChat and DingTalk no longer interfere with each other's SDK loops or long polling when sharing a process.
- Added desktop system notifications: permission requests, scheduled task completion and final replies of long tasks can trigger desktop notifications, reusing deduplication and cooldown logic.
- The desktop composer shows more accurate context usage, supporting live CLI inspection, the initial state of empty sessions, transcript fallback for disconnected sessions and model window changes.
- The terminal page and in-session terminal open in the current working directory first, and keep the cwd when promoted to a standalone terminal tab.
- The diagnostics page can show recent errors, copy an error summary, open the log directory, clear logs and export a redacted diagnostic bundle.

## Fixes

- Fixed the DingTalk bot Client ID / Secret remaining after unbinding; credentials are now cleared via an explicit unbind endpoint instead of relying on a generic config merge that drops `undefined` fields.
- Fixed invisible WeChat agent replies: the send message and typing APIs now check the iLink business ret code, and retry or report the queue error back to the session on failure.
- Fixed the WeChat typing status disappearing too early during long tasks; typing is maintained throughout long tool execution and cancelled on completion or failure.
- Fixed the final answer after a DingTalk permission request sometimes being written above an old AI Card; a permission request now ends the current streaming card, and a new card shows the result after approval.
- Fixed Telegram and other IM adapters having long polling hijacked by leftover old sidecars or a shared multi-platform process; the desktop app cleans up stale sidecars and splits each IM platform into its own sidecar process.
- Fixed IM adapter credential file permissions and pairing file write safety; config directories and credential files use owner-only permissions where possible.
- Fixed an empty desktop session with an all-zero context snapshot showing a misleading 0%.
- Fixed desktop context usage dropping after an assistant reply completes; the latest output tokens are now counted toward the next turn's context, with a local estimate as the lower bound.
- Fixed the transcript fallback for disconnected sessions counting differently from the live `/context`; both now share the same current-context token total logic.
- Fixed context inspection being sent before the prewarm CLI connected to the SDK socket, causing the composer spinner or the first context request to time out.
- Fixed empty sessions wrongly reporting "CLI session is not running"; before the first message is sent the state now clearly shows it is pending calculation.
- Fixed a failed session deletion sometimes polluting later chat startup; a failed file deletion rolls back the deletion marker, avoiding an old session that exists but cannot be started.
- Fixed desktop rewind resume stability: rewind waits for the CLI to exit and drains output first, and empty-transcript placeholder sessions keep the canonical workDir.
- Fixed the desktop permission prompt sometimes being invisible after switching permission mode; changing permission mode restarts the CLI and keeps the prompt visible.
- Fixed untrustworthy macOS notification plugin permission status; macOS now uses native UserNotifications to request authorization, show foreground notifications and send test notifications.
- Fixed inconsistent low-level auth env policy and secrets being displayed by mistake, avoiding saving placeholders when editing Settings JSON.
- Fixed `/context` showing inaccurate context windows for different models, completing built-in model window resolution.

## Docs and tests

- Updated the WeChat and DingTalk IM docs with QR code binding, pairing codes, default project, command discovery and mobile permission approval, plus matching screenshots.
- The `docs/im` overview now covers configuration entries and the security model for all four platforms.
- Added and expanded regression tests for context counting, IM permission, WeChat typing, DingTalk stream state, desktop notifications and adapter config redaction.
- Local PR quality gates cover desktop, server, adapters, native and docs; maintainers are still advised to smoke test real WeChat, DingTalk, Feishu and Telegram accounts before release.

## Other notes

- The GitHub Release body still comes from `release-notes/v0.2.1.md`, so the Markdown no longer has to be copied by hand.
- PR quality gates do not call real models by default; end-to-end WeChat / DingTalk / Feishu / Telegram messaging still needs explicit maintainer verification.
- macOS notifications are now more conservative by default: you must enable desktop notifications in settings and grant system authorization before receiving permission request, task completion or long-task reply notifications.
